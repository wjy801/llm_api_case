# P0 迭代一：契约与身份代码变更记录

## 变更目标

按照 `dev_plan/P0迭代一契约与身份详细开发方案.md` 完成 P0 迭代一代码开发，建立后续质量数据采集、归并和门禁依赖的稳定契约与身份基础，同时保持现有 pytest、请求中间件、`run_master.py` 和 Jenkins 执行行为不变。

## 第一性原理与 TOC 决策

本迭代解决的核心问题不是采集更多数据，而是先冻结“质量事实如何被表达和唯一关联”。

```text
契约不稳定
-> 采集端和归并端理解不一致
-> 报告与门禁口径漂移
-> P1 基线和 Flaky 治理失真
```

```text
身份不稳定
-> 同一用例或接口跨构建无法对齐
-> 趋势、失败复现和请求归属失去稳定对象
-> 质量工程退回文本日志检索
```

因此本次只新增独立 `quality` 包和离线单元测试，不提前接入运行链路。

## 代码改动

### `.gitignore`

- 将原 `/tests` 忽略规则调整为 `/tests/*`。
- 为 `tests/quality/` 增加明确例外，确保本迭代新增测试可以进入版本管理。

### `quality/models.py`

- 新增 `quality.v1` schema version。
- 新增运行、完整性、用例、协议、业务、成本、失败、责任域、置信度和门禁枚举。
- 新增 `RunRecord`、`CaseResult`、`RequestMetric`、`FailureRecord`、`QualitySummary`、`GateDecision` 和 `IntegrityIssue` 等 P0 契约模型。
- 新增 usage、cost、failure fingerprint source 和 gate rule 辅助模型。
- 模型统一使用 Pydantic v2 frozen、extra forbid 和非有限浮点拒绝策略。
- 增加非空身份、非负耗时、attempt、样本量、比率范围、时区和时间顺序校验。

### `quality/redaction.py`

- 新增质量侧递归脱敏，不修改现有日志侧脱敏语义。
- 覆盖 Authorization、Cookie、API Key、token、secret、password、Bearer 文本和高风险随机串。
- 区分身份场景的全部 query 删除与参数摘要场景的非敏感参数保留。
- 新增 canonical JSON，支持 mapping、序列、set、Enum、datetime、Path、Pydantic、dataclass 和自定义对象。
- 保证哈希前先脱敏，并拒绝 NaN/Infinity 进入 canonical JSON。

### `quality/identifiers.py`

- 新增 run、execution、case、param、invocation、request event、interface 和 failure ID 工具。
- `param_hash` 使用脱敏 canonical JSON 的 SHA-256 前 16 位。
- `invocation_id` 使用 `inv-` 加组合哈希前 24 位。
- `interface_id` 使用 `METHOD templated_path protocol`。
- nodeid 支持 Windows/Unix 路径和嵌套参数括号。
- 路径模板化覆盖数字、UUID、长十六进制和保守随机段，并保留有业务语义的模型路径。
- failure fingerprint 去除时间戳、UUID、query、token、内存地址、动态路径 ID 和长数字，同时保留 HTTP 状态码语义。

### `quality/runtime_context.py`

- 新增冻结的 run/case 上下文对象。
- 使用两个独立 `ContextVar` 保存当前运行和当前用例身份。
- 提供 set/get/reset/clear API，支持 Token 嵌套恢复和最终清理。
- 不依赖 pytest，不负责采集或写入。

### `quality/storage.py`

- 新增同目录临时文件加 `os.replace` 的 JSON 原子写入。
- 新增单记录单行的 JSONL append/read。
- 新增损坏 JSONL 文件路径和行号错误定位。
- 新增 `shards/`、`merged/` 目录布局创建函数。
- UTF-8 输出，拒绝非标准 NaN/Infinity JSON。
- 第一版不实现多进程锁，后续通过 worker 分片规避并发写竞争。

### `quality/__init__.py`

- 汇总导出稳定模型、枚举、ID、脱敏、上下文和存储 API。
- 未导出内部正则和低层转换函数。

### `tests/quality/`

- 新增模型序列化、冻结、校验和枚举测试。
- 新增敏感值、query 策略、canonical 稳定性和调用方数据不变测试。
- 新增 ID 稳定性、跨平台 nodeid、路径模板和失败指纹测试。
- 新增 ContextVar 嵌套恢复、隔离和异常清理测试。
- 新增 JSON 原子替换、失败保护、JSONL 格式和目录创建测试。

## 关键实现决策

- `RunRecord.environment` 第一版只要求非空，不提前限制为枚举，避免阻断未来环境扩展。
- `case_id` 使用规范化 nodeid 明文，保证可读和跨构建稳定。
- `param_hash` 固定 16 位，`invocation_id` 固定 `inv-{hash24}`。
- `interface_id` 始终携带协议，避免 HTTP、SSE 和 polling 身份冲突。
- 只有可独立落盘的顶层事实模型携带 `schema_version`；usage、cost 等嵌套值对象不重复携带版本字段。
- 质量侧 canonical 和存储都拒绝 NaN/Infinity，保证产物为严格合法 JSON。
- 本迭代未在任何现有运行时代码中 import `quality`。
