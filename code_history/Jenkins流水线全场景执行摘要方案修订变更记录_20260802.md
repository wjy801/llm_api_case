# Jenkins 流水线全场景执行摘要方案修订变更记录

## 变更日期

2026-08-02

## 变更类型

开发方案修订，不包含业务代码修改。

## 需求变化

原方案只在 Real Smoke 和 Quality 生命周期结束后生成摘要，无法覆盖 framework-only、collect-only 和前序阶段失败的 Jenkins 构建。

修订后的要求是：

```text
每一轮已经进入 Jenkinsfile 执行的流水线
→ 都生成 reports/pipeline-summary.md
```

```text
dev_plan/Jenkins流水线全场景执行摘要初版修改方案.md
```

## 修改文件

```text
dev_plan/Smoke执行摘要初版精简修改方案.md
```

在原方案顶部标记已被全场景方案替代，保留需求演进记录。

## 修订重点

- 主报告身份从 Quality run_id 提升为 Jenkins job + build number。
- 主产物调整为 `reports/pipeline-summary.md`。
- 报告生成时机调整为 Jenkins `post { always }`。
- 覆盖 framework-only、collect-only、Real Smoke 及其组合。
- 新增 PASSED、FAILED、NOT_RUN、BLOCKED、NO_DATA 阶段状态。
- Real Smoke 未启用时不创建 Quality run_id，也不误报质量数据缺失。
- Real Smoke 执行时继续展示请求成功率、重试挽救率、接口耗时 Top 和 Flaky 状态迁移。
- Python 主生成器不可用时由 Jenkins 写入最小兜底摘要。
- 明确 Jenkinsfile 加载前的 SCM/Controller 失败属于系统级保证边界。

## 未修改内容

- 未修改 Python 框架和业务代码。
- 未修改 Jenkinsfile。
- 未执行真实付费接口。
