# Smoke 计费用例最终一致性修复代码变更记录

## 需求

修复 Jenkins 构建 #61 中两个计费用例的时序失败：同步图片调用返回时用量记录仍为 `pending`；异步图片用例错误假设预扣款前余额不变。

## 根因

- 用量记录采用最终一致性，单次立即查询可能得到未结算数据。
- 当前账户采用预扣款，异步任务完成前余额允许发生变化。
- `±0.01` 金额容差正确，不应通过扩大容差掩盖时序问题。

## 代码改动

- `common/base_task.py`：增加用量记录终态轮询，每 2 秒查询一次，最多等待 60 秒；统一覆盖按模型响应和 request id 的计费查询。
- `module/smoke/test_图片生成异步调用.py`：删除与预扣款冲突的中间余额不变断言，保留最终账单一致性断言。
- `tests/test_base_task.py`：验证轮询参数、控制密钥恢复和 pending/terminal 状态识别。
- `tests/quality/test_smoke_billing_settlement.py`：防止重新引入异步任务完成前余额不变假设。

## 验证

- 针对性回归：`53 passed`。
- Smoke 收集：`41 tests collected`，并发池 15，串行池 26。
- Python 编译检查通过。
- 未调用真实收费接口，未触发 Jenkins 流水线。

## 其他用例审查结论

- 同步图片、文本和并发文本计费用例均通过公共计费查询自动获得终态等待能力。
- 发现部分仅提交图片任务的用例没有等待任务及账单收口，可能干扰共享账户的后续余额断言；该问题独立于本次两个失败，留待后续隔离治理。
