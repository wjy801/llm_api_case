# Jenkins 流水线全场景执行摘要初版实现代码变更记录

## 1. 本轮目标

将只在 Real Smoke 中可见的质量观测入口提升为 Pipeline 级执行摘要，使每轮已进入 Jenkinsfile 的构建都能按实际参数和产物生成 `reports/pipeline-summary.md`。初版只保留能直接判断执行效果的信息；请求、重试、耗时和 Flaky 指标仅在 Real Smoke 启用时展示。

## 2. 第一性原理与约束判断

报告的核心价值不是增加统计项，而是回答四个问题：本轮要求执行什么、实际执行了什么、结果如何、下一步处理什么。

本轮 TOC 约束是报告生命周期原先依附于 Real Smoke，导致 framework-only、collect-only 和前序失败构建缺少统一入口。因此生成时机移动到 Jenkins `post { always }`，Quality `run_id` 只作为 Real Smoke 的可选证据，不再作为整份报告的前提。

## 3. 代码改动

### 3.1 新增 Pipeline 报告模块

新增 `pipeline_reporting/`：

- `contracts.py`：构建身份、阶段状态、测试、请求、重试、耗时和 Flaky 展示契约。
- `config.py`：解析 `GENERATE_PIPELINE_SUMMARY`，进程环境优先于 `.env`，默认开启。
- `sources.py`：读取阶段状态、JUnit、collect 输出和本轮 Quality 产物，并校验 `run_id`。
- `builder.py`：计算 `PASS/WARN/FAIL`、阶段状态和建议动作，不执行文件 IO。
- `renderer.py`：输出精简中文 Markdown。
- `service.py`：编排加载、构建、渲染并原子写入报告。
- `__main__.py`：提供阶段状态初始化、更新和报告生成 CLI。

模块依赖边界固定为：核心模型无业务依赖，builder/renderer 只依赖 contracts，Quality 读取集中在 sources，service 只负责编排。

### 3.2 Jenkins 生命周期

修改 `Jenkinsfile`：

- 新增默认开启的 `GENERATE_PIPELINE_SUMMARY` boolean 参数和定时任务参数。
- 初始化 `reports/pipeline-stage-status.json`，在 Framework、Collect、Real Smoke 阶段开始和结束时记录状态。
- 在 Pipeline `post always` 中先生成摘要，再发布 Allure、归档产物和发送邮件。
- Python 主生成器异常时写入最小兜底摘要，且不覆盖原始 Jenkins 结果。
- 开关关闭时不生成主摘要、兜底摘要或邮件链接。
- 邮件仅在 `pipeline-summary.md` 存在时把它作为首个报告入口。

### 3.3 精简指标

- 请求成功率：HTTP 有响应、无超时/传输异常、非 429 且小于 500。
- 重试挽救率：复用请求组 `http_retry_rescue_rate`。
- 接口耗时 Top 5：仅 workload、非 polling，按平均耗时和最大耗时稳定排序。
- Flaky：展示状态迁移方向及新增疑似、确认、恢复、隔离、超期数量。
- Framework/Real Smoke 用例结果从 JUnit 读取并按 invocation/case 身份去重。
- 扩展 `quality.junit` 暴露安全解析后的用例耗时。
- 扩展动态十六进制后缀路径归一化，避免接口耗时排行身份漂移。

### 3.4 配置与文档

修改 `.env.example`、`README.md`、`FRAMEWORK_TEST_SPEC.md`、`JENKINS_MIGRATION_TEMPLATE.md`：

- 增加开关、默认值和优先级说明。
- 将 `pipeline-summary.md` 设为任意流水线的默认人工入口。
- 保留 P0/P1/JUnit/Allure 作为详细证据。
- 更新离线回归基线。

### 3.5 测试

- 新增 Pipeline 报告生成、开关优先级、失败/阻断、四项精简指标测试。
- 新增 `pipeline_reporting` 文件集合、内部依赖 DAG 和 Quality 单点读取边界测试。
- 更新 Jenkinsfile、JUnit 耗时和接口身份归一化测试。
- 报告测试迁入 `tests/quality/`，避免被仓库 `/tests/*` 忽略规则排除。
