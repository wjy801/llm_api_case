## 方案核心

本次方案将 P0 定位为“质量数据底座”，核心不是增加报告页面，而是建立可信质量事实链：

```text
测试执行
-> 稳定身份
-> 结构化采集
-> 分片落盘
-> 唯一归并
-> 完整性校验
-> 失败分类
-> 聚合报告
-> 影子门禁
```

## 关键设计决策

- P0 只做质量事实采集、归并、分类、报告和影子门禁，不做 P1 的历史基线、Flaky 状态机和强制门禁。
- `run_master.py` 负责父级 `run_id`、多次 pytest 阶段 `execution_id` 和最终归并。
- pytest 插件只负责用例级事实采集和 worker 分片写入。
- 请求中间件负责请求 attempt 级指标采集，每次重试单独记录。
- 通过 `contextvars` 在用例执行期间传递 `case_id` 和 `invocation_id`，解决请求指标无法归属用例的问题。
- 质量采集必须 fail-open，采集异常写入完整性问题，不覆盖真实测试结果。
- 影子门禁只输出 `PASS/WARN/BLOCK/NO_DATA`，P0 阶段不改变 CI 退出码。
