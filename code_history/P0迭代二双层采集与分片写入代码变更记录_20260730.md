# P0 迭代二：双层采集与分片写入代码变更记录

## 变更目标

按照 `dev_plan/P0迭代二双层采集与分片写入详细开发方案.md` 完成 P0 迭代二代码开发，把迭代一冻结的 `quality.v1` 契约接入 pytest 生命周期和请求中间件，生成线程安全、worker 独占的 Case、Request 和 Integrity JSONL 分片。

本次开发保留 pytest、xdist、`ThreadPoolExecutor`、请求、重试、轮询、SSE、JUnit、Allure 和原退出码语义，不实现归并、失败分类、最终报告、门禁或 Jenkins 修改。

## 第一性原理与 TOC 决策

本迭代解决的核心问题不是增加日志量，而是形成可信的 Case→Request 事实链。

```text
请求没有真实 case/invocation 上下文
-> 并发请求只能按时间猜测归属
-> 接口指标无法解释测试目的
-> 后续归并和门禁建立在错误事实之上
```

```text
多个 xdist worker 写同一个文件
-> 发生覆盖、交错或损坏
-> JSONL 无法稳定解析
-> 数据完整性不可证明
```

TOC 当前约束是“事实归属和写入所有权”，因此优先级固定为：

```text
不改变原行为
> 不产生错误归属
> 不丢失已知事实
> 指标丰富度
```

## 当前新增的框架能力

### 1. Case→Request 双层质量事实关联能力

- 框架可以同时采集测试用例结果和真实 HTTP 请求指标，不再只看到“用例失败”或“请求失败”的单层事实。
- 每条请求指标都必须归属于明确的 `case_id` 和 `invocation_id`，后续可以从测试目的下钻到具体请求 attempt。
- 一个测试函数对应稳定 `case_id`，一个参数实例对应独立 `invocation_id`，同一测试目的内的并发请求共享所属 Case 身份。

### 2. 参数化与并发场景的稳定身份归属能力

- 参数化用例通过参数 ID 和脱敏参数摘要区分调用实例，避免同一测试函数的多组数据相互覆盖。
- 线程池并发任务通过 ContextVar 上下文复制继承当前 Case 身份，不需要把 `case_id` 逐层侵入业务函数参数。
- 每次真实 HTTP attempt 生成独立 `request_event_id`，重试不会覆盖前一次请求事实。

身份链已经扩展为：

```text
测试函数身份
-> 参数实例身份
-> 并发请求归属
-> 单次 HTTP attempt
-> worker 独立分片
-> 后续唯一归并
```

### 3. pytest 全生命周期采集能力

- 覆盖 setup、call、teardown 三个阶段，不再只采集测试函数主体。
- 能够表达 passed、failed、error、skipped、xfailed 和 xpassed 等 pytest 原生结果。
- collection failure 作为完整性问题记录，不伪造成不存在的测试 Case。

### 4. 多协议请求过程可观测能力

- 普通 HTTP 请求可以采集方法、模板化接口、状态码、耗时、请求 ID、Token usage 和执行结果。
- polling 请求复用原状态判定规则记录每次真实轮询请求，不改变轮询循环和超时语义。
- retry 场景按 attempt 独立采集，同时保留原幂等性和重试策略。
- SSE 请求只采集响应头阶段耗时，不主动消费流正文，保留调用方原生流式处理责任。

### 5. xdist 与并串混合执行的安全分片能力

- 每个 `execution_id + worker_id` 独占 Case、Request 和 Integrity 三类 JSONL 分片，消除多进程共同写文件导致的交错、覆盖和损坏风险。
- xdist controller 只负责统一身份下发，不重复写入 master 数据。
- 并行阶段、串行阶段和直接 pytest 执行都使用无序号的原生阶段语义，阶段身份不再依赖线程池槽位编号。

### 6. 父级运行与阶段执行统一编排能力

- 一次 `run_master.py` 运行内共享同一个 `run_id`，可以把不同执行阶段归入同一次质量运行。
- `execution_id` 区分 `parallel-pool`、`serial-pool` 或手工 pytest 阶段，为后续跨阶段归并提供稳定边界。
- 外部 CI 提供运行身份时可以复用，未提供时由框架生成，并在阶段结束后恢复原环境变量。

### 7. fail-open 与完整性问题显式化能力

- 质量采集异常不会覆盖业务请求结果、pytest 原退出码或原异常传播。
- 缺少 Case 上下文时不生成身份不完整的 RequestMetric，而是记录 `missing_case_context`。
- Case/Request 写入失败会转化为 IntegrityIssue；Integrity 自身失败仅输出脱敏警告，避免采集链路反向阻断测试。

### 8. 数据安全与可回退能力

- URL 使用模板化路径，避免动态资源 ID 导致接口身份碎片化。
- Authorization 等敏感字段不落盘，采集失败日志也保持脱敏。
- `QUALITY_ENABLE=0` 可以关闭整个质量采集链路，恢复原框架行为和原生调用语义。

### 9. 后续质量工程的事实底座能力

本迭代尚未直接实现 merge、分类、聚合、报告和门禁，但已经提供这些能力所需的最小可信事实：

- 稳定的运行、阶段、Case、参数实例和请求 attempt 身份。
- 可独立解析的 worker 分片和显式完整性问题。
- 可用于对账、去重、失败分类、失败指纹和质量门禁的 Case→Request 关联链。

## 代码改动

### `quality/config.py`

- 新增独立质量配置，不污染业务 `Settings`。
- 支持 `QUALITY_ENABLE`、`QUALITY_RUN_ID`、`QUALITY_EXECUTION_ID`、`QUALITY_OUTPUT_DIR`。
- 支持 `1/true/yes/on` 和 `0/false/no/off`。
- 配置读取无目录创建副作用。
- 空身份归一为 `None`，空输出目录回退到 `reports/quality`。

### `quality/collector.py`

- 新增进程级唯一 `QualityCollector`。
- 每个 `execution_id + worker_id` 独占 cases、requests、integrity 三个分片。
- session 初始化只清空当前 worker 自有分片。
- 使用进程内 `RLock` 保护多线程单行 JSONL 写入。
- case/request 写入失败时转换为完整性问题。
- integrity 自身写入失败时只输出脱敏警告，不向业务链路抛出。
- 新增 collector configure/get/reset 生命周期 API。

### `quality/pytest_plugin.py`

- 新增环境变量驱动的 pytest 插件。
- collect-only 和禁用模式保持无副作用。
- `pytest_runtest_protocol` 使用 ContextVar Token 包围完整 setup/call/teardown 生命周期。
- 参数化 identity 同时使用 parameter id 和脱敏 params 生成 `param_hash`。
- `pytest_runtest_logreport` 生成 phase 级 `CaseResult`。
- 正确映射 passed、failed、error、skipped、xfailed、xpassed。
- collection failure 写 `IntegrityIssue`，不伪造测试函数 case。
- xdist controller 只生成和下发统一运行配置，不写分片。
- xdist worker 使用 `gw*` 独立落盘，非 xdist 使用 `master`。
- pytest unconfigure 时恢复 run ContextVar 并释放 collector。

### `quality/request_metrics.py`

- 新增 RequestMetric 构建和安全提取适配器。
- before 阶段记录 `request_event_id` 和 monotonic start。
- after/on_exception 阶段生成每个真实 HTTP attempt 的指标。
- 普通 HTTP 2xx 记 success，非 2xx 和异常记 failed。
- polling 复用现有 `PollingPolicy` 和 `evaluate_polling_response()`。
- SSE 2xx 记 unknown，只统计响应头耗时，不读取流正文。
- 提取明确 request-id header 和非 SSE `request_id` 字段。
- 安全提取 input/prompt、output/completion token usage。
- cost 保持 `source=none`，不提前引入计价逻辑。
- 缺失 case context 时不写非法 RequestMetric，改写 `missing_case_context`。
- 请求采集异常通过中间件转换为 `request_capture_failed`，不覆盖原请求结果。

### `quality/identifiers.py`

- 新增公共 `build_url_template()`。
- `build_interface_id()` 与 RequestMetric 共用同一套路径模板规则。
- 保持 `quality.v1` 身份契约和原 `build_execution_id()` 算法不变。

### `quality/__init__.py`

- 导出质量配置、collector、分片路径和 URL template 公共 API。
- 不导出 pytest 插件内部状态和 request capture 内部属性。

### `common/request_context.py`

- 增加只存在于本地上下文的 `protocol`、`retry_policy`、`polling_policy` 元数据。
- 元数据不进入真实 HTTP 请求参数。
- 现有构造调用通过默认值保持兼容。

### `common/request_middleware.py`

- 新增 fail-open `QualityMetricsMiddleware`。
- collector 启用时插入默认中间件链首位，禁用时原列表不变。
- 显式自定义 middleware 列表仍由调用方完全控制。
- before、after、on_exception 均内部捕获采集异常。

### `common/base_request.py`

- 在内部 RequestContext 创建链路传递 protocol、retry policy 和 polling policy。
- 每个 retry attempt 继续由原 `RetryExecutor` 创建独立 RequestContext。
- polling 调用显式标记 `protocol=polling`，不修改轮询循环或状态机。
- `stream=True` 自动标记为 SSE，不修改调用方消费流的责任。
- 公共 `request/get/post/poll_get` 调用形式不变。

### `common/context_executor.py` 与 `common/__init__.py`

- 新增 `submit_with_context()`。
- 每次任务提交单独调用 `copy_context()`。
- 返回原生 Future，不创建、关闭或等待 executor。
- 保留任务返回值和异常传播。
- 通过 `common` 公共入口延迟导出。

### `run_master.py`

- 一次父级 `run()` 只生成或复用一个 `run_id`。
- 并行阶段使用 `parallel-pool`。

- 每个正式阶段临时设置 `QUALITY_*` 环境变量，结束后恢复原环境。

- collect-only 不生成或注入正式质量身份。
- 保持 `_run_pytest(args)` 和 `_run_serial_pool(args)` 原调用形式，兼容现有测试及 monkeypatch。
- 未触发 merge、report、run.json 或 Jenkins 修改。

## 关键实现决策

- `RequestMetric.case_id` 和 `invocation_id` 保持必填，不新增 orphan 或 nullable 语义。
- 线程池属于业务并发验证能力，本迭代只传播上下文，不取消并发。
- collector 使用进程全局注册，因为它表达当前 worker 的文件所有权；当前 case 仍使用 ContextVar。
- phase 级 CaseResult 使用 `invocation_id + phase` 作为后续归并候选键。
- 普通 HTTP 200 业务错误不做通用正文猜测，由 Case 断言表达。
- polling 总超时不伪造 HTTP 请求事件。
- SSE 不访问 `content/text/json/iter_lines`。
- retryable 同时遵守 method/idempotency 和现有 response/exception policy。
- xdist controller 不创建空 master 分片。
- 固定分片名在每个 session 初始化时只清空当前 worker 文件，防止上次 run 数据混入。

## 验证环境说明

- 本机全局 pytest 自动加载的第三方 `langsmith` 插件缺少 `httpx`，验证时设置 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 并显式加载项目需要的 `allure_pytest`、`pytester` 和测试内部 xdist 插件。
- Windows 上跨盘符临时目录会影响已有嵌套 `pytest.main()` 测试，因此全量验证使用仓库内已忽略的 `reports/pytest-temp-*` 作为 basetemp。
- 以上均为测试环境隔离，不是框架代码缺陷。
