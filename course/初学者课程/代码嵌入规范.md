# 初学者课程代码嵌入规范

## 适用范围

本规范只约束课程正文中的源码、伪代码、命令、配置和数据片段。第二周及后续课程新增或修改代码导读时必须遵守。

## 核心规范

### 1. 渐进展示

- 不得在讲解开始时展示完整文件、完整类或完整调用链代码。
- 每次展示足以完整回答当前问题的代码片段。
- 一个片段只承载一个主要概念、分支或时间粒度。
- 当前片段解释完成后，才能展示下一个函数或分支。
- 完整调用链只能在全部片段讲解完成后用于复盘。

### 2. 嵌入讲述

代码片段前必须说明：

- 当前要回答的问题。
- 代码所在文件与函数。
- 此时阅读它的原因。

代码片段后必须立即说明：

- 输入来自哪里。
- 状态发生了什么变化。
- 输出或异常交给谁。
- 当前函数的责任在哪里结束。

不得连续粘贴多个代码块后再集中解释。应使用问题自然引出下一个片段。

### 3. 以讲解完整为准

- 代码片段不设置行数上限或建议区间。
- 片段长度由当前问题所需的完整上下文决定。
- 不得为了缩短代码而删除影响结论的分支、异常处理、资源清理或返回语句。
- 只有拆分能让讲解顺序更清楚时才拆分，不按行数机械截断。
- 与当前问题无关的 `import`、常量、装饰器和辅助实现不得保留。

### 4. 保持源码保真

- 函数名、参数名、字段名、调用顺序和分支条件必须与当前实现一致。
- 不得静默改写真实源码，也不得把教学示例标成源码原文。
- 使用文件路径和符号名定位代码，不以固定行号作为唯一定位方式。
- 聚焦摘录可用 `...` 省略无关实现，但必须说明片段不完整。
- `...` 不得省略会改变结论的关键分支、异常处理、资源清理或返回语句。
- 伪代码和等价流程必须显式标注，不得伪装成可执行源码。

### 5. 隔离调用分支

- 一个导读段落先选择一条明确主路径，例如“无 Retry 的普通 POST”。
- 未进入的 Retry、Polling、异常或并发分支只说明其存在，不同时展开源码。
- 跨文件调用时，必须先解释责任转移，再展示下游函数。
- 不得把多个分支合并进一个大代码块让初学者自行区分。

### 6. 统一展示边界

- 代码围栏必须标明正确语言；伪代码使用 `text` 或明确的伪代码标识。
- 解释文字写在代码块外，不用大量教学注释改造源码。
- 执行命令与运行输出必须分成两个代码块。
- 不得嵌入真实 API Key、Token、Cookie、账号、生产 URL、私有日志或未脱敏响应。

## 标准顺序

```text
提出问题 → 指明位置 → 展示当前所需的完整片段 → 解释输入、状态、输出与责任 → 引出下一片段
```
