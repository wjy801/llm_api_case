语义关系与所有权完整性

学习P1 Semantic如何归并worker产生的Request Group、Polling Session与Operation分片，再用P0 Manifest和request-metrics证明这些关系引用同一轮可信请求事件。

建议时长 3 小时OperationRequest GroupOwnership
可核验产出：语义实体关系图、所有权完整性表、P0证据绑定说明和本轮Semantic Manifest核验记录。

前序输入

直接上游是Day21提交的P0 Manifest、request-metrics及其Hash；Case、Issue和Failure不是Semantic聚合器输入。

Operation、Request Group、Polling Session与P0请求事件之间可双向核对的所有权图。

01 · First principles

单条请求事实无法表达一次业务操作

一个业务意图可能包含创建请求、多个轮询请求、Retry attempt和SSE流。P0只回答每次attempt发生了什么；Semantic必须把这些事实组织成有所有权的图，又不能复制或改写P0。

实体

Operation、Request Group、Polling Session。

边

Operation拥有Group与Session；Group引用P0 event。

证据

Manifest绑定同run的P0 Manifest和Request Metrics Hash。

TOC约束：核心约束是引用完整性。只要存在孤儿Group、跨Operation引用或不属于P0的event，整张关系图就不能作为指标来源。

02 · Semantic entities

三类主实体回答不同粒度的问题

实体核心身份与引用回答的问题
RequestGroupRecordgroup_id、operation_id、可选polling_session_id、attempt_event_ids一次逻辑请求经历了几次真实attempt，首尾传输结果如何？
PollingSessionRecordsession_id、operation_id、request_group_ids轮询了几次、观察了哪些状态、sleep多久、最终为何结束？
OperationRecordoperation_id、group_ids、session_ids、evidence_refs一次业务意图的结果、总耗时、usage和证据范围是什么？

三类实体都继承run、execution、worker、case、invocation和created_at身份。关系验证不仅比较ID是否存在，还比较这些作用域身份是否一致。

03 · Collection chain

运行时上下文逐步积累关系，结束时固化记录

begin Operation→start Group→bind RequestContext→collect attempt event IDs→finish Group→finish Operation

semantic_context.py使用ContextVar维护当前Operation、Request Group与Polling Session。Runtime Adapter只拿到handle并调用上下文函数；SemanticCollector负责把完成的不可变模型写到worker分片。

嵌套Operation通过owned语义复用父操作；并发请求使用独立上下文与唯一ID；未正常结束的pending对象由finalize_pending()写为INCOMPLETE，而不是假装成功。

04 · Ownership graph

Operation是业务边界，Group是P0事件的唯一语义所有者

关系必须满足
Operation → Groupoperation.request_group_ids包含Group，且group.operation_id反向一致
Group → Request Event每个attempt_event_id存在于P0 request-metrics，且不能被多个Group拥有
Operation → Sessionoperation.polling_session_ids包含Session，且session.operation_id一致
Session → Groupsession引用的Group存在、属于同一Operation，且group.polling_session_id指回Session
Operation usage → Eventsource与missing event都来自该Operation拥有的Group，两个集合不重叠

evidence_refs是Operation最终引用的证据集合，不允许引用图外事件。所有权规则让后续指标能够精确回答分母来自哪里。

05 · Polling semantics

poll_count、Request Group数量和attempt数量是三个不同事实

一次轮询调用通常每轮产生一个Request Group，而每个Group又可能因Retry产生多个attempt event。因此：

poll_count

业务状态查询次数。

group count

Polling Session引用的逻辑请求次数。

attempt count

所有Group实际发出的HTTP attempt总数。

Polling Session还保存状态序列、首次观察偏移、sleep总时长、terminal_status与final_outcome。Operation的polling_total_ms和polling_sleep_ms来自Session事实，不从请求数量猜测。

06 · SSE and async task

SSE与异步任务把跨阶段请求收口到一个Operation

SSE

HTTP Group提供响应头阶段事实，Stream事件补充首数据、首内容、流持续时间和complete/interrupted/error/not_consumed终态。

Async task

创建请求、多个轮询Group和媒体结果usage共同属于一个async_task Operation，Polling Session只是其中的子关系。

Operation的usage保存input/output token、媒体数量或时长、来源event IDs、缺失event IDs和完整度。缺失不会变成0；CONTROL流量角色也不会被伪装成WORKLOAD。

07 · Semantic merge

先扫描Semantic分片，再载入P0证据验证关系

  1. 写status=merging的Semantic Manifest。
  2. 扫描request-groups、polling-sessions、operations和semantic integrity分片，执行run过滤、Schema验证与重复处理。
  3. 读取P0 merged/manifest.json和request-metrics.jsonl，验证P0状态、run_id与输出Hash。
  4. 建立P0 request_event索引，执行关系与身份验证。
  5. 原子写出四类Semantic合并文件并计算Hash。
  6. 提交status=complete Manifest，保存p0_evidence的Manifest Hash和Request Metrics Hash。

扫描顺序不改变硬依赖：Semantic最终必须用已提交的P0 Manifest与request-metrics验证关系。在阶段图上，它的直接上游是P0，产物只向Metrics输出；Flaky Import从同一可信P0独立起步，不串接在Semantic或Metrics之后。

08 · Relationship integrity

存在性、唯一性、反向引用和身份必须同时成立

验证层典型问题后果
存在性Group引用不存在的P0 event或Session生成ERROR Issue
唯一性同一个event被两个Group拥有所有权冲突
反向引用Operation列出Group，但Group.operation_id不一致关系不闭合
作用域身份run相同但case、invocation或execution不一致跨上下文污染
用量证据usage引用Operation之外的event或source/missing重叠usage来源不可解释

最终完整性状态仍采用complete、degraded、failed。关系问题通常是ERROR，因为它会破坏后续指标的成员资格；采集阶段显式标记的不完整记录可以形成WARN和degraded。

10 · Current-run graph

生成本轮语义图并核对所有权

$python = '.\.venv\Scripts\python.exe'
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'; $root = Join-Path 'reports/course' ('day22-quality-' + $stamp)
$names = @('QUALITY_ENABLE','QUALITY_SEMANTIC_ENABLE','QUALITY_METRICS_ENABLE','QUALITY_FLAKY_HISTORY_ENABLE','QUALITY_FLAKY_STATE_ENABLE','QUALITY_OUTPUT_DIR','QUALITY_RUN_ID','GENERATE_ALLURE_REPORT','GENERATE_HISTORY_REPORT')
$old = @{}; foreach ($name in $names) { $old[$name] = [Environment]::GetEnvironmentVariable($name) }
function Read-Jsonl([string]$path) { @(Get-Content -LiteralPath $path | Where-Object { $_.Trim() } | ForEach-Object { $_ | ConvertFrom-Json }) }
try {
  $env:QUALITY_ENABLE = '1'; $env:QUALITY_SEMANTIC_ENABLE = '1'; $env:QUALITY_METRICS_ENABLE = '0'
  $env:QUALITY_FLAKY_HISTORY_ENABLE = '0'; $env:QUALITY_FLAKY_STATE_ENABLE = '0'
  $env:QUALITY_OUTPUT_DIR = $root; $env:QUALITY_RUN_ID = 'course-day22-' + $stamp
  $env:GENERATE_ALLURE_REPORT = 'FALSE'; $env:GENERATE_HISTORY_REPORT = 'FALSE'
  $allure = Join-Path $root 'allure-results'
  & $python run_master.py module/offline_framework_example -n 2 --alluredir=$allure
  if ($LASTEXITCODE -ne 0) { throw ('Runner exit=' + $LASTEXITCODE) }
  $manifest = Get-Content -LiteralPath (Join-Path $root 'semantic/merged/manifest.json') -Raw | ConvertFrom-Json
  $events = Read-Jsonl (Join-Path $root 'merged/request-metrics.jsonl')
  $groups = Read-Jsonl (Join-Path $root 'semantic/merged/request-groups.jsonl')
  $sessions = Read-Jsonl (Join-Path $root 'semantic/merged/polling-sessions.jsonl')
  $operations = Read-Jsonl (Join-Path $root 'semantic/merged/operations.jsonl')
  $eventIds = @($events.request_event_id); $operationIds = @($operations.operation_id)
  $missingEvents = @($groups | ForEach-Object { $_.attempt_event_ids } | Where-Object { $eventIds -notcontains $_ })
  $orphanGroups = @($groups | Where-Object { $operationIds -notcontains $_.operation_id })
  [pscustomobject]@{ Status=$manifest.status; Integrity=$manifest.integrity_status; Operations=$operations.Count; Groups=$groups.Count; Sessions=$sessions.Count; Events=$events.Count; MissingEvents=$missingEvents.Count; OrphanGroups=$orphanGroups.Count; P0ManifestHash=$manifest.p0_evidence.manifest_sha256 }
}
finally { foreach ($name in $names) { [Environment]::SetEnvironmentVariable($name,$old[$name]) } }

11 · Design choice

设计选择与适用边界

现方案用稳定身份显式建模Operation、Request Group和Polling Session，并验证正向引用、反向引用与唯一所有者。
替代方案按时间邻近、URL相同或日志顺序推断请求属于哪个业务操作。
选择理由重试、轮询和异步任务会打乱时间与顺序；显式身份和所有权能给出确定关系，并允许发现孤儿与多重归属。
不适用条件完全无跨请求语义的一次性调用可只保留事件事实；若以分布式Trace为权威来源，则需要接入trace/span模型而非重复造身份。
