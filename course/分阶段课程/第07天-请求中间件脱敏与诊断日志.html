WEEK 2 · DAY 07

请求中间件、脱敏与诊断日志

今天只解决一个核心问题：怎样在同一次HTTP attempt里增加脱敏和日志能力，同时保证真实请求参数、Response和原始传输异常仍由业务主链拥有。

RequestContextMiddleware orderRedacted copyOriginal error first
本课结果：能够沿真实发送轨与诊断轨解释每个对象的输入输出、字段变化、成功终点和异常终点，并说明为什么日志能力不能改写业务事实。

01 · 目标与核心约束

诊断能力的第一性约束：只能观察，不能夺走业务所有权

如果日志直接修改待发送参数，诊断层就改变了系统行为；如果异常日志覆盖Session异常，诊断层又改变了失败事实。两类污染都会让测试结果失真。

发送事实

Session消费context.method、context.url和context.kwargs，这些对象决定真正发出的请求。

attempt扩展事实

context.attributes可承载脱敏副本、Logger、attempt索引和中间件错误等扩展事实；这些事实不替代发送参数。

成功事实

Session返回的同一个Response经过after_response后继续回到Task和测试断言。

失败事实

Session抛出的原始异常经过on_exception后仍被重新抛出；诊断失败只能成为附加信息。

污染问题的因果链

诊断代码直接改kwargs→Session收到不同输入→业务行为变化→日志不再是观察者

@staticmethod
def _copy_request_kwargs(kwargs: dict[str, Any]) -> dict[str, Any]:
    copied_kwargs: dict[str, Any] = {}
    for name, value in kwargs.items():
        try:
            copied_kwargs[name] = deepcopy(value)
        except Exception:
            copied_kwargs[name] = value
    return copied_kwargs

def _build_request_context(..., **kwargs: Any) -> RequestContext:
    url = self._build_url(path)
    request_kwargs = self._copy_request_kwargs(kwargs)
    request_kwargs.setdefault("timeout", self.config.timeout)
    request_kwargs["timeout"] = self.retry_executor.clamp_timeout(
        request_kwargs["timeout"], deadline,
    )
    headers = dict(request_kwargs.pop("headers", None) or {})
    request_kwargs["headers"] = self._merge_headers(
        headers, inherit_session_headers=inherit_session_headers,
    )
    return RequestContext(
        method=method.upper(), path=path, url=url, kwargs=request_kwargs,
        attach_log=attach_log, request_step_name=request_step_name,
        response_step_name=response_step_name,
        protocol=protocol or ("sse" if request_kwargs.get("stream") else "http"),
        retry_policy=retry_policy, polling_policy=polling_policy,
    )
源码精讲

深拷贝保护调用者；随后补timeout、合并Header并构造Context。此时context.kwargs就是Session将使用的标准化输入。

承接对象

模块Request传来的method、path和传输kwargs。

职责

隔离调用者引用，并归一化一次attempt。

处理顺序

构造URL → 深拷贝 → 补/裁剪timeout → 合并Header → 创建Context。

输入输出

输入为method/path/kwargs；输出为RequestContext。

字段/状态变化

边界

深拷贝失败时保留原引用，不保证所有自定义对象绝对隔离。

    self._run_before_middlewares(context)
    try:
        response = self.session.request(
            method=context.method, url=context.url, **context.kwargs,

边界

class RedactionMiddleware:
    REDACTED_KWARGS_ATTR = "redacted_kwargs"

    def before_request(self, context: RequestContext) -> None:
        context.attributes[self.REDACTED_KWARGS_ATTR] = (
            redact_request_kwargs(context.kwargs)
        )

def redact_request_kwargs(kwargs: Mapping[str, Any]) -> dict[str, Any]:
    redacted: dict[str, Any] = {}
    for name, value in kwargs.items():
        lowered_name = name.lower()
        if lowered_name == "headers":
            redacted[name] = redact_headers(value)
        elif lowered_name in {"params", "json", "data"}:
            redacted[name] = redact_sensitive_data(value)
        elif _is_sensitive_key(name):
            redacted[name] = REDACTED_VALUE
        else:
            redacted[name] = _safe_copy(value)
    return redacted
源码精讲

顶层按参数类型分派，最终只新增一个attributes字段；真实kwargs不被替换。

承接对象

发送轨中的context.kwargs。

职责

生成可记录副本，隐藏敏感Header和敏感键值。

处理顺序

遍历kwargs → 分派规则 → 递归替换 → 写入attributes。

输入输出

输入为真实kwargs；输出为新的脱敏字典。

字段/状态变化

attributes["redacted_kwargs"]从不存在变为安全副本。

边界

识别范围由显式规则决定，不是任意秘密的自动发现器。

class LoggingMiddleware:
    LOGGER_ATTR = "api_call_logger"

    def before_request(self, context: RequestContext) -> None:
        logger_kwargs = context.attributes.get(
            RedactionMiddleware.REDACTED_KWARGS_ATTR,
            context.kwargs,

            self.get_logger(context).attach_failure(error)

def _request_parts(self, prepared_request=None) -> dict[str, str]:
    if prepared_request is None:
        method = self.method
        url = redact_url(self.url) or self.url
        headers = self.kwargs.get("headers")
        body = self._fallback_request_body()
    else:
        method = prepared_request.method or self.method
        url = redact_url(prepared_request.url or self.url) or self.url
        headers = redact_headers(prepared_request.headers)
        body = self._format_body_value(prepared_request.body)
    return {
        REQUEST_CURL_ATTACHMENT_NAME: self._format_curl(prepared_request),
        "请求行": f"{method} {url} HTTP/1.1",
        "请求头": self._format_headers(headers),
        "请求体": body,
    }

def build_curl(
    prepared_request: requests.PreparedRequest,
    *,
    redact_headers: Iterable[str] | None = DEFAULT_REDACT_HEADERS,
    multiline: bool = True,
) -> str:
    if not isinstance(prepared_request, requests.PreparedRequest):
        raise TypeError("prepared_request must be a requests.PreparedRequest instance")
    method = prepared_request.method or "GET"
    url = redact_url(prepared_request.url)
    if not url:
        raise ValueError("prepared_request.url is empty")
    redacted_header_names = _normalized_header_names(redact_headers)
    parts = [f"curl -X {method.upper()} {_shell_quote(url)}"]
    for name, value in prepared_request.headers.items():
        header_value = REDACTED_VALUE if name.lower() in redacted_header_names else str(value)
        parts.append(f"-H {_shell_quote(f'{name}: {header_value}')}")
    body = _request_body_to_text(prepared_request.body, prepared_request.headers.get("Content-Type", ""))
    if body is not None:
        parts.append(f"--data-raw {_shell_quote(body)}")
    return _join_command_parts(parts, multiline=multiline)

Response携带PreparedRequest时，Logger不盲信早期快照，而是对最终URL、Header和body再次脱敏；cURL由独立构造器生成后作为请求附件的一部分。

07 · 异常所有权

中间件自己的失败必须服从请求主错误

before/after失败会包装并标出来源；on_exception失败发生在已有Session异常之后，只能附加note，不能把原错误替换掉。

三个阶段的失败策略

正常阶段快速失败，异常阶段保留主错误

本段测试与生产符号

测试类/函数tests/test_base_request_middleware.py::TestBaseRequestMiddlewarePipelinequalified symbolsBaseRequest._run_before_middlewares / _run_after_middlewares / _run_exception_middlewares
def _run_before_middlewares(self, context: RequestContext) -> None:
    for middleware in self.middlewares:
        try:
            middleware.before_request(context)
        except Exception as error:
            raise RuntimeError(
                f"Request middleware {type(middleware).__name__} failed in before_request"
            ) from error

def _run_after_middlewares(
    self, context: RequestContext, response: requests.Response,
) -> None:
    for middleware in self.middlewares:
        try:
            middleware.after_response(context, response)
        except Exception as error:
            raise RuntimeError(
                f"Request middleware {type(middleware).__name__} failed in after_response"
            ) from error

def _run_exception_middlewares(
    self, context: RequestContext, request_error: BaseException,
) -> None:
    middleware_errors: list[RuntimeError] = []
    for middleware in self.middlewares:
        try:
            middleware.on_exception(context, request_error)
        except Exception as error:
            middleware_errors.append(RuntimeError(
                f"Request middleware {type(middleware).__name__} failed in on_exception"
            ))
            middleware_errors[-1].__cause__ = error
    if middleware_errors:
        context.attributes["middleware_exception_errors"] = middleware_errors
        for middleware_error in middleware_errors:
            request_error.add_note(str(middleware_error))
源码精讲

before和after阶段没有需要保留的Session主错误，首个失败会包装为阶段明确的RuntimeError；on_exception阶段已有request_error，所以诊断错误只能收集并附注。

承接对象

Context、Middleware列表和Session原异常。

职责

标明阶段故障来源，维护原始请求异常优先级。

处理顺序

before/after首错立即包装；exception按顺序收集全部错误后统一附注。

输入输出

before/after失败输出RuntimeError；exception阶段结束后仍重抛原request_error。

字段/状态变化

新增attributes["middleware_exception_errors"]与异常notes。

边界

attributes是attempt级扩展事实空间，不只承载诊断，也可承载attempt索引等运行事实。

08 · 现有证据边界

测试证明局部合同，源码解释完整执行链

测试直接证明不能扩大为
TestRequestPipeline.test_middleware_does_not_mutate_original_payload普通module调用后payload值未变，回显等于原值。所有自定义对象都能深拷贝，或全部敏感规则均覆盖。
TestRedactionMiddleware.test_redacts_copy_without_mutating_original_kwargs典型Header、params和嵌套JSON被替换，原kwargs保持真实值。未知字段名或任意文本格式都会自动识别秘密。
test_runs_middlewares_in_registration_orderbefore、Session、after按注册顺序并共享Context。after反向执行，或每个Middleware拥有不同Context。
test_exception_middleware_error_does_not_hide_original_request_errorSession Timeout仍是抛出对象，诊断错误成为note。before/after失败也采用同一附注语义。

09 · 整理答案

直接给出四个判断与依据

脱敏副本不参与发送

是。Session读取context.kwargs；脱敏结果只写入attributes。

默认顺序含四段

是。真实顺序为RuntimeObservation → MediaResource → Redaction → Logging。

附件所有者不是Middleware

是。格式化、PreparedRequest二次脱敏和附件写入由ApiCallLogger拥有；cURL由build_curl拥有。

诊断异常不能覆盖Session异常

不能。on_exception错误进入attributes并通过add_note()附加，随后裸raise原异常。

Design · 设计选择与边界

选择双轨，而不是“先改写再发送”

当前方案

发送轨保存真实、标准化后的kwargs；attempt级attributes保存脱敏副本、Logger、重试索引等扩展事实。

直接改写方案

在真实kwargs上替换敏感值后再发送，会改变认证Header、查询参数和业务body。

选择理由

双轨同时满足行为正确性与诊断安全性；默认顺序表达数据依赖。

适用边界

脱敏规则需要维护；deepcopy失败会回退原对象，不能把隔离能力绝对化。

10 · 课后流转总图

11 · 完整复述

用一段连续叙述讲清双轨关系

测试把payload交给Task，Task委托模块Request把它翻译成POST、相对路径和json参数。BaseRequest消费框架控制项，并在构造RequestContext时对当前dict payload深拷贝、补timeout、合并Header，由此建立本次attempt的真实发送轨；若某个值无法deepcopy，代码会回退原对象。before Middleware按RuntimeObservation、MediaResource、Redaction、Logging顺序执行，任一before失败都会包装为RuntimeError且不会进入Session。Session始终读取真实method、url和kwargs。成功时全部after Middleware仍按注册顺序运行，Logging阶段中的ApiCallLogger对PreparedRequest二次脱敏、调用build_curl并生成附件；只有全部after成功才返回同一个Response，after失败会包装为RuntimeError。Session失败时全部on_exception Middleware接收原异常，诊断失败只add_note，最后仍重抛Session原异常。

12 · 验收结论

满足以下事实，才算真正掌握Day7

对象连续

能从payload讲到RequestContext、attributes、ApiCallLogger、PreparedRequest、Response/异常。

顺序准确

能写出RuntimeObservation → MediaResource → Redaction → Logging，且三个阶段均按注册顺序。

所有权准确

Middleware编排生命周期；ApiCallLogger拥有格式化与附件；build_curl拥有cURL文本。

边界保守

不把deepcopy说成绝对隔离，不把attributes缩窄为仅诊断空间，不让日志错误覆盖原异常。

验收句：真实kwargs负责发送，attempt级attributes承载扩展事实，ApiCallLogger负责安全格式化与附件，Response和原异常保留最终业务所有权。
