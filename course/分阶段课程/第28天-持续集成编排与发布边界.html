参数决定是否执行，阶段只调用稳定入口

真实Smoke默认关闭；执行时Jenkins设置Quality开关并调用run_master.py，不解析业务响应。

Jenkinsfile::parameters / Real Smoke stage · 非连续选段：参数声明与阶段执行主体
parameters {
    booleanParam(name: 'RUN_FRAMEWORK_TESTS', defaultValue: true, description: '执行 tests 目录下的离线框架测试。')
    booleanParam(name: 'RUN_COLLECT_ONLY', defaultValue: true, description: '仅收集 Smoke 用例并统计分池，不调用真实接口。')
    booleanParam(name: 'RUN_REAL_SMOKE', defaultValue: false, description: '执行真实 Smoke；会产生外部调用和费用，默认关闭。')
    booleanParam(name: 'GENERATE_PIPELINE_SUMMARY', defaultValue: true, description: '为本轮构建生成 reports/pipeline-summary.md 执行摘要。')
    booleanParam(name: 'ALWAYS_SEND_REPORT_EMAIL', defaultValue: false, description: '成功构建也发送报告邮件；失败或不稳定构建始终发送。')
    choice(name: 'USE_CHINA_ENVIRONMENT', choices: ['TRUE', 'FALSE'], description: 'TRUE 使用中国环境，FALSE 使用海外环境。')
    string(name: 'SMOKE_TARGET', defaultValue: 'module/smoke', description: '真实 Smoke 的目标目录、文件或 pytest nodeid。', trim: true)
    choice(name: 'TEST_PARALLEL_WORKERS', choices: ['off', 'auto', '2', '4', '8'], description: 'off 关闭并发；auto/2/4/8 启用 pytest-xdist 并设置 worker 数量。')
}

stage('Real Smoke') {
    when { expression { return params.RUN_REAL_SMOKE } }
    steps {
        script {
            updatePipelineStageStatus('real_smoke', 'NO_DATA')
        }
        ciPowerShell('''
        $target = $env:SMOKE_TARGET
        $env:QUALITY_ENABLE = '1'
        $env:QUALITY_SEMANTIC_ENABLE = '1'
        $env:QUALITY_METRICS_ENABLE = '1'
        $env:QUALITY_FLAKY_HISTORY_ENABLE = '0'
        $env:QUALITY_FLAKY_STATE_ENABLE = '0'
        $env:QUALITY_OUTPUT_DIR = 'reports/quality'
        ./.venv/Scripts/python.exe run_master.py $target @parallelArgs --junitxml=reports/smoke-tests.xml
        ''')
    }
}

动作所有权

输入验证

危险真实调用必须由RUN_REAL_SMOKE=true显式开启；target和并发只是传给稳定Runner入口。

状态变化

阶段开始先记NO_DATA，结束由post按真实结果更新PASSED/FAILED。

Artifact所有权

Runner/pytest写execution-result、JUnit、Allure和Quality目录；Jenkins只准备路径与环境。

边界

Groovy不读取接口payload、不计算Metrics、不改变Flaky状态。

3

阶段状态函数只调用Reporting CLI并失败开放

初始化记录哪些阶段被选择；更新函数记录阶段事实。两者不判断测试数量和质量阈值。

Jenkinsfile::initializePipelineStageStatus / updatePipelineStageStatus · 两个完整函数
void initializePipelineStageStatus() {
    if (!pipelineSummaryEnabled()) {
        echo 'Pipeline summary generation is disabled; stage status initialization skipped.'
        return
    }
    try {
        ciPowerShell("""
        ./.venv/Scripts/python.exe -m pipeline_reporting initialize-stages `
          --framework-tests ${params.RUN_FRAMEWORK_TESTS} `
          --smoke-collect ${params.RUN_COLLECT_ONLY} `
          --real-smoke ${params.RUN_REAL_SMOKE}
        """)
    } catch (error) {
        echo "Pipeline stage status initialization failed open: ${error.getMessage()}"
    }
}

void updatePipelineStageStatus(String stageName, String status) {
    if (!pipelineSummaryEnabled()) {
        return
    }
    try {
        ciPowerShell("""
        ./.venv/Scripts/python.exe -m pipeline_reporting set-stage `
          --name '${stageName}' `
          --status '${status}'
        """)
    } catch (error) {
        echo "Pipeline stage status update failed open: ${stageName}=${status}: ${error.getMessage()}"
    }
}

阶段事实

输入

布尔参数决定初始NOT_RUN/NO_DATA语义；stageName/status来自当前阶段post。

状态变化

Python CLI拥有pipeline-stage-status.json格式与原子写入，Groovy只传值。

失败开放

状态记录失败只写日志，不覆盖测试原始退出码或构建结果。

失败边界

报告可能缺少阶段文件并产生warning，但不能因此把实际失败改成成功。

4

post先生成统一Report，再发布Artifact和通知

generatePipelineSummary()调用Python一次生成四种视图；失败时只写不含推测数量的fallback。

Jenkinsfile::generatePipelineSummary / post always · 非连续选段：完整生成函数与发布顺序
void generatePipelineSummary() {
    if (!pipelineSummaryEnabled()) {
        echo 'Pipeline summary generation is disabled by GENERATE_PIPELINE_SUMMARY.'
        return
    }
    try {
        if (!fileExists('.venv/Scripts/python.exe') || !fileExists('pipeline_reporting/__main__.py')) {
            throw new IllegalStateException('Python report generator is unavailable in the workspace.')
        }
        withEnv([
            "PIPELINE_BUILD_RESULT=${currentBuild.currentResult ?: currentBuild.result ?: 'SUCCESS'}",
            "PIPELINE_DURATION_MS=${currentBuild.duration ?: 0}",
            "QUALITY_ENABLE=${params.RUN_REAL_SMOKE}",
        ]) {
            ciPowerShell('''
            ./.venv/Scripts/python.exe -m pipeline_reporting generate `
              --workspace . `
              --output reports/pipeline-summary.md `
              --machine-output reports/pipeline-summary.json `
              --email-subject-output reports/pipeline-email-subject.txt `
              --email-html-output reports/pipeline-email.html `
              --dotenv .env
            ''')
        }
        if (!fileExists('reports/pipeline-summary.md')) {
            throw new IllegalStateException('Pipeline summary generator completed without output.')
        }
    } catch (error) {
        echo "Pipeline summary generation failed open: ${error.getMessage()}"
        writeFallbackPipelineSummary()
    }
}

always {
    script {
        generatePipelineSummary()
    }
    allure includeProperties: false, jdk: '', results: [[path: 'allure-results']]
    archiveArtifacts artifacts: 'allure-results/**, reports/**', allowEmptyArchive: true
}

发布与失败边界

输入事实

当前构建结果、耗时和是否执行真实Smoke作为Reporting context；源Artifact已由前序阶段写出。

产物

Python一次生成Markdown、JSON、邮件主题和HTML；Jenkins随后发布Allure并归档reports。

顺序

先生成再归档、再通知，确保邮件和归档引用同一轮Report。

兜底

fallback不推测用例数，也不修改build result；它只证明详细报告生成失败。

01 · Question

CI的本质是编排，不是复制业务判断

如果Groovy再次解析JUnit、Quality并计算结论，Python与Jenkins会形成两套规则。项目让Jenkins只维护阶段执行事实，并调用pipeline_reporting生成统一结论。

边界：只静态阅读Jenkinsfile与迁移模板，不触发真实Job、真实Smoke、付费接口或持久Flaky状态。

主流水线与迁移合同

03 · Stages

阶段顺序体现依赖约束

Checkout→Check Runtime Env→Prepare Python Env→Framework Unit Tests→Collect Smoke Cases→Real Smoke→post发布

Prepare阶段清理并重建reports/，随后初始化pipeline-stage-status；可选测试阶段由参数控制。

04 · Parameters

危险动作必须显式开启

RUN_FRAMEWORK_TESTS默认true，运行离线tests。
RUN_COLLECT_ONLY默认true，只收集Smoke并统计分池。
RUN_REAL_SMOKE默认false，会产生真实外部调用与费用。
GENERATE_PIPELINE_SUMMARY控制统一报告生成。
TEST_PARALLEL_WORKERSoff/auto/固定worker数。
安全默认：静态学习不改变这些参数；Smoke只允许collect-only。

05 · Stage status

Jenkins记录执行事实，Python解释状态

initializePipelineStageStatus把未启用阶段写成NOT_RUN、启用但未完成阶段写成NO_DATA；各阶段post再调用set-stage更新PASSED或FAILED。Groovy不计算最终PipelineConclusion。

阶段开始

先置NO_DATA，避免阶段中断后被误判成功。

阶段结束

success/failure/unstable/aborted显式更新。

06 · Publish

post负责统一生成、归档和通知

JUnit由Jenkins junit步骤发布测试结果。
Allure发布allure-results，Runner仍拥有原始生命周期。
Artifacts归档allure-results/**与reports/**。
Summary调用Python生成Markdown、JSON和邮件文件。
Email优先读取Python邮件视图，缺失时使用有限fallback。

07 · Boundary

哪些判断属于Python，哪些动作属于Jenkins

Python拥有

收集、分池、pytest退出码、Quality聚合、来源信任、PipelineReport结论与视图。

Jenkins拥有

参数、agent、超时、凭据环境、阶段调度、插件发布、归档和通知时机。

允许fallback

报告生成失败时写有限摘要并继续归档。

禁止复制

Groovy不应重写Metrics、Flaky或Report结论算法。

11 · Design choice

设计选择与适用边界

现方案Jenkins只负责编排阶段、环境、归档和通知，Python拥有测试状态、质量语义与报告结论。
替代方案在Jenkinsfile/Groovy中重复实现测试结果解析、质量阈值和业务状态判断。
选择理由领域规则保留在可单测、可本地复现的Python代码中，CI平台只处理执行动作，减少平台锁定和双份规则漂移。
不适用条件组织没有Python运行环境或发布必须经过独立审批/签名服务时，应调用版本化领域服务与发布控制面，而不是把规则临时塞回Groovy。
