DAY 15 · AUTHORITATIVE PLAN, CONSERVED SETS

权威收集与并串行调度

调度器的第一责任不是尽量并发，而是证明每个被选中的 nodeid 恰好出现一次：要么进入并发池，要么进入串行池，绝不能两边都进或两边都不进。

建议 1.5～2.5 小时前置：第14天参数计划实践只做离线收集核心：pytest_execution.py / scheduling.py
完成标志：能解释 Runner 为何只权威收集一次；能从 pytest item 得到 nodeid/marker 计划；能用互斥并集证明分池守恒，并区分“不传 -n 的全量串行”与“传 -n 的并发优先、串行收尾”。

def collect_test_case_items(
    test_path: str | Path,
    pytest_args: Sequence[str] = (),
) -> CollectionResult:
    collector = _CaseCollector()
    stdout = StringIO()
    stderr = StringIO()
    args = [
        "--collect-only",
        "-q",
        "-o",
        "addopts=",
        *pytest_args,
        str(test_path),
    ]
    with redirect_stdout(stdout), redirect_stderr(stderr):
        exit_code = int(pytest.main(args, plugins=[collector]))

    if collector.duplicate_nodeids:
        duplicates = ", ".join(sorted(collector.duplicate_nodeids))
        raise RuntimeError(f"pytest collection produced duplicate nodeids: {duplicates}")
    return CollectionResult(
        raw_pytest_exit_code=exit_code,
        cases=tuple(collector.items),
        stdout=stdout.getvalue(),
        stderr=stderr.getvalue(),
    )

run_orchestration/pytest_execution.py::_CaseCollector.pytest_collection_finish · 连续源码第195至212行
class _CaseCollector:
    def __init__(self) -> None:
        self.items: list[CollectedTestCase] = []
        self.duplicate_nodeids: set[str] = set()

    def pytest_collection_finish(self, session: pytest.Session) -> None:
        seen: set[str] = set()
        for item in session.items:
            if item.nodeid in seen:
                self.duplicate_nodeids.add(item.nodeid)
                continue
            seen.add(item.nodeid)
            self.items.append(
                CollectedTestCase(
                    nodeid=item.nodeid,
                    markers=frozenset(marker.name for marker in item.iter_markers()),
                )
            )

输入从哪里来

session.items是pytest完成选择、参数化与marker继承后的最终结果。

谁负责收口

易混点

run_orchestration/scheduling.py::split_test_cases · 连续源码第8至31行
def split_test_cases(
    cases: Sequence[CollectedTestCase],
    serial_marker: str = DEFAULT_SERIAL_MARKER,
) -> tuple[tuple[str, ...], tuple[str, ...]]:
    parallel_cases: list[str] = []
    serial_cases: list[str] = []
    seen: set[str] = set()

    for case in cases:
        if case.nodeid in seen:
            raise ValueError(f"duplicate nodeid in execution plan: {case.nodeid}")
        seen.add(case.nodeid)
        if serial_marker in case.markers:
            serial_cases.append(case.nodeid)
        else:
            parallel_cases.append(case.nodeid)

    parallel = tuple(parallel_cases)
    serial = tuple(serial_cases)
    if set(parallel) & set(serial):
        raise ValueError("parallel and serial execution pools overlap")
    if set(parallel) | set(serial) != seen:
        raise ValueError("execution pool union differs from the authoritative plan")
    return parallel, serial

纯分池不变量

输入从哪里来

唯一输入是冻结的CollectedTestCase序列和serial marker名称。

当前消费什么

每个case只检查nodeid是否重复、marker是否包含serial。

输出写到哪里

nodeid恰好追加到parallel或serial列表，最后冻结为tuple。

谁负责收口

函数自己验证重复、交集和并集，不把坏计划交给执行器。

成功/失败边界

成功返回互斥两池；任一不变量失败立即抛错，禁止带病执行。

04 · Duplicate defense

重复nodeid必须在执行前失败

相同nodeid出现两次意味着“身份”已经无法区分两项。框架设置两层防线：收集器发现pytest items重复时拒绝；纯调度器再次验证输入计划，防止其他调用方注入重复项。

防线一：收集边界

_CaseCollector 用本地seen记录item.nodeid；重复项加入 duplicate_nodeids，不重复追加到items。

收集结束后抛 RuntimeError，并列出重复身份。

防线二：调度边界

split_test_cases() 再用seen校验每个case；同一nodeid第二次出现立即抛 ValueError。

纯函数不信任调用来源。

为何不能静默去重

静默去重会隐藏参数化ID冲突、插件重复注册或上游计划损坏，只留下“少跑一条”的假正常结果。

失败比猜测哪条是真的更安全。

为何数量相等仍不够

计划为 {a,b}，若分池为 {a,c}，数量仍是2，但b丢失且c越界。必须比较集合成员，不只比较count。

集合等式优先于计数相等。
身份原则：若两个逻辑用例需要分别执行，它们必须拥有不同且稳定的nodeid；参数化用例应提供稳定、可读、不含密钥的参数ID。

08 · Evidence boundary

collect-only能证明什么，不能证明什么

计划证据和执行证据必须分层。collect-only在Quality生命周期与执行事实写入前返回，因此它非常适合证明收集和分池，却不能冒充正式运行产物。

可以从输出核对

  • 打印nodeid总数和每个具体nodeid。
  • parallel/serial分类数量。
  • 总数 = 并发数 + 串行数。
  • nodeid文本是否唯一。
  • 黄金nodeid是否只出现一次。
  • 空选择返回pytest exit 5。

不能从输出声称

  • 用例通过或失败。
  • 两个池实际启动和完成。
  • xdist真正同时运行了多少任务。
  • Quality expected_case_count 已写入证据。
  • execution-result.json 已生成。
  • Allure/JUnit产物完整。

def collect_test_case_items(
    test_path: str | Path,
    pytest_args: Sequence[str] = (),
) -> CollectionResult:
    collector = _CaseCollector()
    stdout = StringIO()
    stderr = StringIO()
    args = [
        "--collect-only",
        "-q",
        "-o",
        "addopts=",
        *pytest_args,
        str(test_path),
    ]
    with redirect_stdout(stdout), redirect_stderr(stderr):
        exit_code = int(pytest.main(args, plugins=[collector]))

    if collector.duplicate_nodeids:
        duplicates = ", ".join(sorted(collector.duplicate_nodeids))
        raise RuntimeError(f"pytest collection produced duplicate nodeids: {duplicates}")
    return CollectionResult(
        raw_pytest_exit_code=exit_code,
        cases=tuple(collector.items),
        stdout=stdout.getvalue(),
        stderr=stderr.getvalue(),
    )

def split_test_cases(
    cases: Sequence[CollectedTestCase],
    serial_marker: str = DEFAULT_SERIAL_MARKER,
) -> tuple[tuple[str, ...], tuple[str, ...]]:
    parallel_cases: list[str] = []
    serial_cases: list[str] = []
    seen: set[str] = set()

    for case in cases:
        if case.nodeid in seen:
            raise ValueError(f"duplicate nodeid in execution plan: {case.nodeid}")
        seen.add(case.nodeid)
        if serial_marker in case.markers:
            serial_cases.append(case.nodeid)
        else:
            parallel_cases.append(case.nodeid)

    parallel = tuple(parallel_cases)
    serial = tuple(serial_cases)
    if set(parallel) & set(serial):
        raise ValueError("parallel and serial execution pools overlap")
    if set(parallel) | set(serial) != seen:
        raise ValueError("execution pool union differs from the authoritative plan")
    return parallel, serial
阅读答案

结论：split_test_cases把权威集合纯粹拆成互斥且并集守恒的并行池与串行池。机制：遍历时先拒绝重复nodeid，再按serial marker分类；最后检查两池无交集且并集等于seen。

        arg = args[index]
        if arg in {"-n", "--numprocesses", "--dist"}:
            index += 2
            continue
        if arg.startswith("--numprocesses=") or arg.startswith("--dist="):
            index += 1
            continue
        cleaned.append(arg)
        index += 1
    return cleaned
阅读答案

结论：清理仅覆盖白名单形式，不会自动识别所有xdist别名。机制：独立的-n、--numprocesses、--dist会连同后一值跳过，--numprocesses=与--dist=形式单独跳过，其余参数保留。
