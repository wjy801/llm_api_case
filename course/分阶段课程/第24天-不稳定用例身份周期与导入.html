2

prepare_flaky_import()先验Artifact，再折叠Case事实

文件存在、磁盘Hash、run/Manifest合同与integrity全部成立后，Case和Failure才会被解析为候选。

quality/flaky_importer.py::prepare_flaky_import · 连续选段
def prepare_flaky_import(request: FlakyImportRequest) -> PreparedFlakyImport:
    output_dir = request.quality_output_dir.resolve()
    paths = {
        "run_record": output_dir / "run.json",
        "manifest": output_dir / "merged" / "manifest.json",
        "case_results": output_dir / "merged" / "case-results.jsonl",
        "failures": output_dir / "merged" / "failures.jsonl",
        "integrity_issues": output_dir / "merged" / "integrity-issues.jsonl",
    }
    for name, path in paths.items():
        if not path.is_file():
            raise FlakyImportError(
                "artifact_missing",
                f"required P0 artifact is missing: {name}",
            )

    source_hashes = {name: _file_sha256(path) for name, path in paths.items()}
    run_record = _read_model(paths["run_record"], RunRecord)
    manifest = _read_json_object(paths["manifest"])
    _validate_run_and_manifest(request.run_id, run_record, manifest)
    _validate_output_hashes(manifest, source_hashes)

    case_results = _read_jsonl_models(paths["case_results"], CaseResult, request.run_id)
    failures = _read_jsonl_models(paths["failures"], FailureRecord, request.run_id)
    integrity_issues = _read_jsonl_models(
        paths["integrity_issues"],
        IntegrityIssue,
        request.run_id,
    )
    _validate_run_integrity_issues(run_record, integrity_issues)
    _validate_integrity_issues(integrity_issues)

    environment = normalize_flaky_environment(run_record.environment)
    fingerprint_version = _manifest_text(manifest, "fingerprint_version")
    fold = fold_case_observations(
        case_results,
        failures,
        environment=environment,
        fingerprint_version=fingerprint_version,
    )
    source_digest = _source_digest(request.run_id, source_hashes)

信任顺序

输入验证

五个P0文件缺一不可；Hash在领域解析前读取，Manifest再证明目标Hash与当前字节一致。

身份事实

run_id、environment、fingerprint version和execution profile进入后续身份计算。

产物所有权

prepare阶段拥有候选、排除原因、source digest和导入元数据，不拥有SQLite提交。

失败边界

Manifest不完整、run未结束、integrity失败或Hash不符都会在数据库创建前抛FlakyImportError。

3

三个Hash键把逻辑用例、语义周期和run级观察分开

materialize_observation()先取得当前epoch，再生成flaky_key与observation_id。

quality/flaky_importer.py::build_epoch_scope_key / build_flaky_key / build_observation_id · 非连续选段：三个完整函数
def build_epoch_scope_key(
    case_id: str,
    environment: str,
    execution_profile: str,
) -> str:
    payload = {
        "case_id": _required_text(case_id, "case_id"),
        "environment": normalize_flaky_environment(environment),
        "execution_profile": normalize_stored_execution_profile(execution_profile),
    }
    return f"epoch-scope-v1-{_full_hash(payload)}"

def build_flaky_key(
    case_id: str,
    param_hash: str,
    environment: str,
    execution_profile: str,
    state_epoch: int,
) -> str:
    if state_epoch < 1:
        raise ValueError("state_epoch must be greater than or equal to 1")
    payload = {
        "case_id": _required_text(case_id, "case_id"),
        "param_hash": _required_text(param_hash, "param_hash"),
        "environment": normalize_flaky_environment(environment),
        "execution_profile": normalize_stored_execution_profile(execution_profile),
        "state_epoch": state_epoch,
    }
    return f"flaky-v1-{_full_hash(payload)}"

def build_observation_id(run_id: str, flaky_key: str) -> str:
    payload = {
        "run_id": _required_text(run_id, "run_id"),
        "flaky_key": _required_text(flaky_key, "flaky_key"),
    }
    return f"observation-v1-{_full_hash(payload)}"
quality/flaky_store/import_service.py::materialize_observation · 连续选段
epoch_scope_key = build_epoch_scope_key(
    candidate.case_id,
    candidate.environment,
    candidate.execution_profile,
)
scope = repository.epoch_scope(connection, epoch_scope_key)
if scope is None:
    repository.insert_epoch_scope(connection, epoch_scope_key, candidate, now)
    state_epoch = 1
else:
    expected = {
        "case_id": candidate.case_id,
        "environment": candidate.environment,
        "execution_profile": candidate.execution_profile,
        "identity_rule_version": candidate.identity_rule_version,
        "environment_rule_version": candidate.environment_rule_version,
        "execution_profile_rule_version": candidate.execution_profile_rule_version,
    }
    for field, value in expected.items():
        if scope[field] != value:
            raise FlakyStoreError(
                "epoch_scope_conflict",
                f"epoch scope field {field!r} is incompatible with current rules",
            )
    state_epoch = int(scope["current_epoch"])

身份所有权

epoch_scope_key

只绑定逻辑Case、环境和执行profile，回答“哪组样本共享语义周期”。

flaky_key

再加入param_hash和state_epoch，回答“当前周期内哪个参数样本可跨run比较”。

observation_id

加入run_id，确保同一样本每个run最多一条Observation。

失败边界

规则版本与当前epoch不兼容时必须显式reset；代码拒绝静默把新规则数据混入旧历史。

4

FlakyStore.import_run()拥有事务，导入服务拥有幂等规则

Facade打开数据库并包裹事务；领域服务先判断NOOP/冲突，再写run、Observation并复核数量。

quality/flaky_store/facade.py::FlakyStore.import_run · 完整类方法
def import_run(
    self,
    metadata: FlakyRunMetadata,
    candidates: Sequence[CaseObservationCandidate],
) -> StoreImportOutcome:
    import_service.validate_import_candidates(metadata, candidates)
    with self.repository.connection(require_existing=False) as connection:
        initialization = initialize_store(
            connection, self.repository, self.migrations_directory
        )
        with self.repository.transaction(connection):
            return import_service.import_run(
                connection,
                self.repository,
                metadata,
                candidates,
                initialization=initialization,
            )

事务与失败边界

验证

候选数必须等于metadata中的eligible_count；数据库路径、迁移与quick check由Store初始化负责。

幂等

同run_id且同source digest返回NOOP；同run不同digest或同digest不同run都拒绝覆盖。

状态变化

run审计行、epoch scope和Observation在同一事务中提交，最终计数必须与物化列表一致。

回滚边界

任何冲突、插入失败或数量不一致都由事务回滚，不能留下“run已导入但Observation不完整”的半状态。

03 · Call chain

导入从可信P0事实开始

ImportRequest→run.json与P0 Manifest→身份/Hash校验→case-results、failures、integrity-issues→折叠Case阶段→候选Observation→Store事务

校验与完整性处理均在P0支线内完成。

04 · Identity

三个键回答三个问题

对象组成作用
epoch_scope_keycase_id + environment + execution_profile定义语义周期范围。
flaky_keycase_id + param_hash + environment + execution_profile + state_epoch定义可比较状态序列。
observation_idrun_id + flaky_key同run同身份只贡献一条Observation。

05 · Epoch

Epoch是显式语义周期

state_epoch从1开始。仅当用例语义或实现边界明确变化时，flaky-reset-epoch才记录actor与reason并开启新周期；普通PASS/FAIL不会自动增加epoch。

注意：param_hash进入flaky_key但不进入epoch scope，因此reset会切断同Case、同环境、同profile下的旧参数历史。

06 · Observation

Observation是run级事实

Importer按(run_id, invocation_id)聚合setup、call、teardown结果，筛选最终PASS或FAIL，再补充environment、execution_profile、failure fingerprint、epoch和身份键。

所有权：P0产生单轮Case事实；Importer翻译成跨run Observation；Store负责持久化与唯一性。

07 · Idempotency

同来源NOOP，冲突来源拒绝

同run + 同digest

返回NOOP，inserted_count为0。

同run + 不同digest

run_source_conflict。

不同run + 同digest

source_digest_conflict。

首次导入

Observation与import run在同一事务提交，计数不一致则回滚。

11 · Design choice

设计选择与适用边界

现方案用case_id标识逻辑用例、param_hash区分参数样本、epoch表达语义周期，并以来源身份事务化导入Observation。
替代方案只用nodeid或用例名称跨run匹配，导入时直接upsert并覆盖已有记录。
选择理由参数变化与语义重置不会被误判为同一样本；同来源NOOP、冲突来源拒绝可保持历史不可篡改与重放幂等。
不适用条件随机模糊测试、一次性生成样本或无法稳定序列化参数的场景，需要另设输入指纹、采样与保留策略。
