WEEK 4 · DAY 18

运行时观察接口

只学习common/runtime_hooks/：Day18的职责是让公共请求、Retry、Polling和SSE通过中性Protocol发出事件；它不决定Quality是否启用，也不把事件写成质量产物。Noop保证默认可运行，Provider与Lease保证一次生命周期始终回到启动它的实现。

建议时长 2.5～3 小时ProtocolContextVarLease
可核验产出：Runtime Hooks对象关系图、事件边界表、依赖方向证明和Quality关闭下的本轮Runner记录。

01 · First principles

公共层需要可观察，但不能依赖观察后端

HTTP控制流属于common；Quality只是潜在消费者。如果common直接导入Quality，关闭Quality或Quality故障就会威胁请求主路径。

产生事件

common知道请求开始、响应、异常、Retry等待、Polling状态和SSE行。

保持中性

公共模型只使用运行时枚举、元数据和不透明handle。

后端翻译

具体观察后端决定如何把事件保存为自己的事实。

TOC约束：关键约束是依赖方向。只要观察异常能替代业务异常，或公共层需要Quality才能导入，观察接口就破坏了框架主干。

02 · Code first walkthrough

从Provider切换测试理解为什么必须保存Lease

开始事件与结束事件必须回到同一个观察后端；Provider只表示当前默认值，Lease才拥有已开始生命周期的配对责任。

本节主线：启动Hooks被保存，Provider变化不改变收口对象

Runtime Hooks只观察业务控制流，不接管HTTP、Polling或SSE终止。

2

Provider用ContextVar保存当前默认Hooks

Token负责恢复嵌套绑定。

common/runtime_hooks/provider.py::get_runtime_hooks / bind_runtime_hooks / reset_runtime_hooks
def get_runtime_hooks() -> RuntimeHooks:
    return _RUNTIME_HOOKS.get()


def bind_runtime_hooks(hooks: RuntimeHooks) -> Token[RuntimeHooks]:
    if hooks is None:
        raise TypeError("hooks must not be None")
    return _RUNTIME_HOOKS.set(hooks)


def reset_runtime_hooks(token: Token[RuntimeHooks]) -> None:
    _RUNTIME_HOOKS.reset(token)

Provider边界

输入输出

bind返回Token，reset恢复上层上下文。

并发

ContextVar提供上下文隔离；跨线程仍需复制上下文。

不负责

它不决定已开始Operation的结束后端。

begin_operation()冻结Hooks，finish_operation()按Lease收口

观察异常失败开放，业务异常仍由业务层传播。

common/runtime_hooks/lifecycle.py::finish_operation / _safe_call
def finish_operation(
    lease: RuntimeOperationLease,
    outcome: RuntimeOperationOutcome,
) -> None:
    if not lease.owned:
        return
    try:
        _safe_call(lease.hooks.finish_operation, lease.native_handle, outcome)
    finally:
        _reset_operation(lease)


def _safe_call(function: Any, *args: Any, **kwargs: Any) -> None:
    try:
        function(*args, **kwargs)
    except Exception:
        return

所有权和异常

Lease

保存Hooks、handle、owned和上下文Token。

嵌套

子Operation复用父Operation时只有所有者发finish。

边界

只吞普通Exception；BaseException不在fail-open范围。

02 · Dependency boundary

四层边界把控制流与事实实现分开

层职责允许依赖
业务能力与HTTP拥有请求、重试、轮询、流消费控制流只依赖common.runtime_hooks
Runtime Hooks定义中性事件、生命周期和Providerrequests与common模型，不依赖Quality
观察后端实现Protocol并翻译事件可以依赖Runtime Hooks与自身模型
Runner/pytest在执行上下文中绑定和重置后端通过插件生命周期管理

tests/quality/test_common_quality_boundary.py会扫描common静态导入，并在Quality不可用时实际导入BaseRequest和streaming，证明公共路径独立。

03 · Protocol surface

Protocol覆盖四组生命周期，而不是暴露后端对象

能力组关键方法公共层传递内容
Operationbegin_operation、finish_operation、detach_operation种类、名称、流量角色、model_id与终态
Request Groupstart_request_group、bind_request_context、finish_request_group接口、协议、最大尝试数与Retry等待
Request Attemptrequest_started、request_succeeded、request_failedRequestContext、Response或异常
Polling / Streambegin_polling_session、状态观察、sleep、stream bind/line/finish状态序列、等待、SSE行和终态

Protocol返回object | None作为native handle。common不读取其内部字段，只把它带回同一后端，保持观察模型封装。

04 · Noop and provider

Provider决定当前实现，默认永远是Noop

provider.py使用ContextVar[RuntimeHooks]保存当前实现，默认值是单例NoopRuntimeHooks。get_runtime_hooks()读取当前上下文；bind_runtime_hooks()返回Token；reset_runtime_hooks(token)恢复之前的绑定。

Noop

所有观察方法返回中性空值或空handle，不写文件、不导入Quality、不影响业务返回。

ContextVar

绑定随复制上下文传播，可被项目的context executor带到线程任务，同时允许嵌套绑定正确恢复。

Provider不负责创建后端。谁拥有执行生命周期，谁负责绑定和重置；第20天会看到Quality runtime plugin如何承担这一职责。

05 · Lease ownership

Lease保存启动时Hooks，防止结束事件发错后端

Operation、Request Group、Polling和Stream都用Lease包装hooks + native_handle；只有Operation Lease额外保存owned + context_token。即使生命周期中途Provider切换，结束操作仍调用Lease保存的原Hooks。

字段或机制作用
hooks固定本生命周期的观察后端
native_handle保存后端私有身份，common只透传
owned仅Operation Lease使用：嵌套Operation复用父Operation时，只有所有者发出finish
context_token仅Operation Lease使用：结束或detach后恢复上一个活动Operation

_safe_call()和_safe_result()只捕获Exception并返回安全默认值；KeyboardInterrupt、SystemExit等BaseException不在该fail-open范围。

06 · Operation and request group

Operation表达一次业务意图，请求组表达一次可重试调用

begin_operation()先检查当前活动Operation。存在父Operation时返回owned=False的Lease，避免嵌套能力重复创建业务操作；不存在时构造RuntimeOperationMetadata并调用当前Hooks。

operation_scope()把终态映射固定下来：正常结束为SUCCESS；Timeout为TIMEOUT；KeyboardInterrupt或SystemExit为INTERRUPTED；其他异常为FAILED，并始终重新抛出原异常。

Request Group围绕Retry总流程：开始时记录method、path、protocol和configured_max_attempts；每次真实attempt通过RequestContext绑定；结束时补充实际Retry等待。Request Attempt事件则紧贴BaseRequest一次真实Session调用。

Operation→Request Group→Attempt 1→wait→Attempt N→Group finish

07 · Polling and stream

长生命周期用专用Lease保持开始与结束配对

Polling

开始session后记录每次状态、sleep秒数和最终Outcome。RuntimePollingObservation同时拥有Operation与Polling Lease，只允许完成一次。

SSE

Response返回后把Stream Lease附着到响应对象；后续迭代行和最终关闭可能发生在另一个调用点，但仍回到启动时Hooks。

Polling错误会按异常类型映射为FAILURE、UNKNOWN、TIMEOUT或INTERRUPTED，并同步映射Operation终态。SSE区分COMPLETE、INTERRUPTED、ERROR和NOT_CONSUMED，避免“拿到响应”被误写成“完整消费”。

Design decision

设计选择与适用边界

现方案替代方案选择理由不适用条件
common只依赖中性Protocol，通过ContextVar Provider选择实现，长生命周期用Lease固定启动时Hooks，默认实现为Noop。公共请求代码直接调用Quality，使用可变全局单例，或把事件发到无配对约束的通用事件总线。依赖方向保持向内，Quality缺失或故障不改变业务控制流；Lease还能防止开始和结束落到不同后端。需要跨进程、可持久化或至少一次投递的观察事件时，进程内Protocol不够，应增加消息传输、幂等键和消费确认。

阅读问题默认Noop、bind Token与reset如何形成可恢复绑定？

from __future__ import annotations

from contextvars import ContextVar, Token

from common.runtime_hooks.noop import NoopRuntimeHooks
from common.runtime_hooks.protocol import RuntimeHooks


_NOOP_RUNTIME_HOOKS = NoopRuntimeHooks()
_RUNTIME_HOOKS: ContextVar[RuntimeHooks] = ContextVar(
    "common_runtime_hooks",
    default=_NOOP_RUNTIME_HOOKS,
)


def get_runtime_hooks() -> RuntimeHooks:
    return _RUNTIME_HOOKS.get()


def bind_runtime_hooks(hooks: RuntimeHooks) -> Token[RuntimeHooks]:
    if hooks is None:
        raise TypeError("hooks must not be None")
    return _RUNTIME_HOOKS.set(hooks)


def reset_runtime_hooks(token: Token[RuntimeHooks]) -> None:
    _RUNTIME_HOOKS.reset(token)
阅读答案

结论：Runtime Provider是可恢复的ContextVar逻辑状态，默认实现为Noop。机制：get读取当前值，bind拒绝None后set并返回Token，reset用Token恢复先前绑定；已创建Lease不会随Provider切换迁移。

源码执行依据

ContextVar提供Noop默认值；bind设置hooks并返回Token；reset恢复先前值。

状态结果

改变当前逻辑上下文中的Provider绑定。

证据结论

Provider是ContextVar逻辑状态，可传播也可恢复。

答案边界

切换Provider不会自动迁移已经创建的Lease。

Flow summary · Runtime observation

第18天总图：业务控制流如何安全地产生中性观察事件

业务函数拥有控制流，Hooks只接收事件；Lease保证开始与结束落在同一个后端。

1

bind_runtime_hooks()

执行上下文绑定Noop、Recorder或Quality Adapter。

→

Provider状态

ContextVar保存当前Hooks和恢复Token。

2

begin_operation()

创建或复用Operation Lease。

→

所有权

Lease冻结启动Hooks、handle、owned和Token。

3

Request / Polling / Stream观察函数

业务层只发送已发生的运行事件。

→

中性事实

method、path、attempt、状态和耗时尚未解释成Quality结论。

4

RuntimeHooks实现

Noop忽略，Recorder测试，Adapter翻译。

→

后端状态

实现可切换，同一Lease仍回到启动Hooks。

5

finish_operation() / _safe_call()

按Lease收口并恢复上下文。

→

业务边界

普通观察异常不替换HTTP响应、业务异常或pytest结果。

核心结论

Provider决定现在默认用谁；Lease决定已开始生命周期必须回到谁。
