def test_run_collect_only_prints_pool_counts_without_execution(monkeypatch, capsys):
    monkeypatch.setattr(
        pytest_execution,
        "collect_test_case_items",
        lambda test_path, pytest_args=(): _collection(
            CollectedTestCase("test_a.py::test_parallel", frozenset()),
            CollectedTestCase("test_b.py::test_serial", frozenset({"serial"})),
        ),
    )
    monkeypatch.setattr(
        pytest_execution,
        "run_pytest",
        lambda args: pytest.fail("collect-only should not execute pytest"),
    )

    exit_code = run_master.run("tests", extra_pytest_args=["--collect-only", "-q"], numprocesses="2")

    captured = capsys.readouterr()
    assert exit_code == 0
    assert "Parallel pool cases: 1" in captured.out
    assert "Serial pool cases: 1" in captured.out

先读断言，再读实现

允许发生

权威收集返回两个nodeid，并按serial标记分成两个池。

禁止发生

如果Runner调用正式run_pytest，替身会立即让测试失败。

验收结果

退出码为0，输出包含两个池的数量；这证明的是计划形成，不是业务用例通过。

3

parse_args()划分参数所有权

框架只消费自己认识的参数，未知项原样保留给pytest。

run_orchestration/cli.py::parse_args · 完整函数
def parse_args(argv: Sequence[str]) -> tuple[argparse.Namespace, list[str]]:
    parser = argparse.ArgumentParser(description="API test framework runner")
    parser.add_argument(
        "target",
        nargs="?",
        help=f"Test collection path. Defaults to {DEFAULT_TEST_PATH}.",
    )
    parser.add_argument(
        "--test-path",
        dest="test_path",
        help=f"Test collection path. Defaults to {DEFAULT_TEST_PATH}.",
    )
    parser.add_argument(
        "-n",
        "--numprocesses",
        dest="numprocesses",
        help="pytest-xdist worker count, for example auto, 2, 4.",
    )
    parser.add_argument(
        "--dist",
        dest="dist",
        help=(
            "pytest-xdist distribution strategy, for example load, "
            "loadscope, worksteal."
        ),
    )
    parser.add_argument(
        "--serial-marker",
        dest="serial_marker",
        default=DEFAULT_SERIAL_MARKER,
        help=(
            "Marker name for cases that must run serially. "
            f"Defaults to {DEFAULT_SERIAL_MARKER}."
        ),
    )
    parser.add_argument(
        "--parallel-first",
        action="store_true",
        help=(
            "Compatibility flag. Passing -n already enables "
            "parallel-first execution."
        ),
    )
    parsed_args, pytest_args = parser.parse_known_args(list(argv))
    parsed_args.test_path = (
        parsed_args.test_path or parsed_args.target or DEFAULT_TEST_PATH
    )
    return parsed_args, pytest_args

两份输出承担不同责任

parsed_args

保存目标路径、并发数量、分发策略和串行标记等Runner拥有的字段。

pytest_args

--collect-only、-q等未知参数不会被CLI吞掉，而是继续交给pytest执行层。

默认路径

优先级是--test-path、位置参数target、最后才是默认测试目录。

02 · 第一性原理

为什么简单接口脚本会逐渐演变成框架

单条脚本能解决一次验证，但当环境、业务、并发、报告和历史治理同时变化时，混在一个文件里的代码会让失败原因不可定位。

简单接口脚本

通常把URL、payload、HTTP调用、断言和日志放在同一个测试函数中。优点是起步快，缺点是变化互相牵连。

准备数据
→ requests发送请求
→ assert判断
→ print输出

当前测试框架

把不同变化方向分开，由稳定公共入口连接。业务用例不需要知道质量聚合和报告实现。

业务表达
→ 公共请求执行
→ pytest编排
→ 中性事实观察
→ 报告与治理

问题是怎样逐层放大的

业务场景增加
公共代码被复制
行为与证据不一致
失败无法归因
第一性原理结论框架的价值不是“封装requests”，而是让同类变化只有一个实现源，让每次执行只产生一套可解释事实。

04 · 执行主线

一次collect-only究竟发生了什么

点击步骤按顺序播放。重点观察“权威收集”和“提前返回”：它们解释了为什么collect-only能给出计划，却不进入正式执行。

collect-only已经完成

导入测试模块、pytest权威收集、获得nodeid与marker、分出并发池和串行池、打印数量。

提前返回

正式执行尚未开始

不运行测试函数，不执行用例fixture，不进入测试池，不初始化Allure Runner生命周期，不创建Quality运行身份和执行事实文件。

会发生：测试收集

pytest需要导入模块才能识别测试类、测试函数、参数和marker。因此“没有执行用例”不等于“什么都没有导入”。

不会发生：业务HTTP

规范用例把业务请求放在测试执行或fixture使用阶段；collect-only不运行这些动作。

会发生：打印计划

输出nodeid、并发池数量、串行池数量和收集总数，供人和后续报告解析。

不会发生：Quality产物

Runner在创建Quality生命周期之前返回，不生成run_id、质量目录或机器证据。

Design Choice · Boundary

设计选择与适用边界：先从稳定入口和collect-only建立全局地图

现
当前方案

从run_master.py稳定入口追踪权威收集、分池与提前返回，再映射module、common、Runner、Quality、Reporting五层。

替
替代方案

按目录逐文件阅读，或直接运行完整测试后从日志反推架构。

因
选择理由

稳定入口暴露真实编排边界；collect-only保留收集事实又避开业务调用与Quality副作用，最适合第一天建立可验证地图。

界

定位具体实现缺陷、资源泄漏或运行期状态错误时，只看collect-only不足，必须进入对应调用链并执行最小离线测试。

def parse_args(argv: Sequence[str]) -> tuple[argparse.Namespace, list[str]]:
    parser = argparse.ArgumentParser(description="API test framework runner")
    parser.add_argument(
        "target",
        nargs="?",
        help=f"Test collection path. Defaults to {DEFAULT_TEST_PATH}.",
    )
    parser.add_argument(
        "--test-path",
        dest="test_path",
        help=f"Test collection path. Defaults to {DEFAULT_TEST_PATH}.",
    )
    parser.add_argument(
        "-n",
        "--numprocesses",
        dest="numprocesses",
        help="pytest-xdist worker count, for example auto, 2, 4.",
    )
    parser.add_argument(
        "--dist",
        dest="dist",
        help=(
            "pytest-xdist distribution strategy, for example load, "
            "loadscope, worksteal."
        ),
    )
    parser.add_argument(
        "--serial-marker",
        dest="serial_marker",
        default=DEFAULT_SERIAL_MARKER,
        help=(
            "Marker name for cases that must run serially. "
            f"Defaults to {DEFAULT_SERIAL_MARKER}."
        ),
    )
    parser.add_argument(
        "--parallel-first",
        action="store_true",
        help=(
            "Compatibility flag. Passing -n already enables "
            "parallel-first execution."
        ),
    )
    parsed_args, pytest_args = parser.parse_known_args(list(argv))
    parsed_args.test_path = (
        parsed_args.test_path or parsed_args.target or DEFAULT_TEST_PATH
    )
    return parsed_args, pytest_args
阅读答案

Runner 识别 target、--test-path、-n/--numprocesses、--dist、--serial-marker、--parallel-first；parse_known_args 将未知项原样留给 pytest。路径依次取 --test-path、target 或默认值。

源码执行依据

注册target/test-path、numprocesses、dist、serial-marker和parallel-first，再以parse_known_args分离Runner参数与pytest_args。

状态结果

补全最终test_path；不执行测试，也不消费collect-only、报告或其他pytest参数。

证据结论

Runner参数所有权和未知pytest参数透传是显式实现。
