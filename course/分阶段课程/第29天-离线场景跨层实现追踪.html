common/task_capabilities/media_generation.py::MediaGenerationCapability.create_and_poll_media_generation · 完整类方法
def create_and_poll_media_generation(
    self,
    request_client: BaseRequest,
    payload: dict[str, Any],
    *,
    poll_interval: float = 2,
    poll_timeout: float | None = None,
    polling_policy: PollingPolicy = DEFAULT_MEDIA_POLLING_POLICY,
    retry_policy: RetryPolicy | None = None,
    create: Callable[[BaseRequest, dict[str, Any]], requests.Response] | None = None,
    extract_task_id: Callable[[requests.Response], str] | None = None,
    poll: Callable[..., requests.Response] | None = None,
) -> requests.Response:
    create_call = create or self.create_media_generation
    extract_call = extract_task_id or self.extract_task_id
    poll_call = poll or self.poll_media_generation_result
    with operation_scope(
        RuntimeOperationKind.ASYNC_TASK,
        name="media_generation",
        role=RuntimeTrafficRole.WORKLOAD,
        model_id=model_id_from_kwargs({"json": payload}),
    ):
        create_response = create_call(request_client, payload)
        task_id = extract_call(create_response)
        return poll_call(
            request_client,
            task_id,
            poll_interval=poll_interval,
            poll_timeout=poll_timeout,
            polling_policy=polling_policy,
            retry_policy=retry_policy,
        )

委托与状态

输入

Task接收Request、payload、PollingPolicy、RetryPolicy和总超时，不复制payload。

状态变化

capability先创建、提取task_id，再轮询；ASYNC_TASK Operation覆盖整段业务动作。

所有权

BaseTask拥有稳定业务API；capability拥有创建+提取+轮询的编排；HTTP仍属于Request。

失败边界

create、task_id提取或poll任一失败直接结束Operation并向测试传播。

3

Media capability把业务动作翻译成Request的POST与poll_get

创建请求和轮询请求都进入BaseRequest主干；Retry只包围单次请求，Polling拥有跨请求deadline与状态循环。

common/task_capabilities/media_generation.py::MediaGenerationCapability.create_media_generation / poll_media_generation_result · 非连续选段：两个完整类方法
def create_media_generation(
    self,
    request_client: BaseRequest,
    payload: dict[str, Any],
) -> requests.Response:
    with operation_scope(
        RuntimeOperationKind.HTTP,
        name="media_generation_create",
        role=RuntimeTrafficRole.WORKLOAD,
        model_id=model_id_from_kwargs({"json": payload}),
    ):
        return request_client.post(self.media_generations_path, json=payload)

def poll_media_generation_result(
    self,
    request_client: BaseRequest,
    task_id: str,
    *,
    poll_interval: float = 2,
    poll_timeout: float | None = None,
    polling_policy: PollingPolicy = DEFAULT_MEDIA_POLLING_POLICY,
    retry_policy: RetryPolicy | None = None,
) -> requests.Response:
    with operation_scope(
        RuntimeOperationKind.POLLING,
        name="media_generation_polling",
        role=RuntimeTrafficRole.WORKLOAD,
    ):
        return request_client.poll_get(
            self.media_task_path_template.format(task_id=task_id),
            poll_interval=poll_interval,
            poll_timeout=poll_timeout,
            polling_policy=polling_policy,
            retry_policy=retry_policy,
        )

协议与可靠性

输入翻译

create把payload放入JSON body；poll把task_id格式化为资源路径，并传递Polling/Retry策略。

状态变化

POST产生create Response；poll_get在总deadline内产生多个Request Group和attempt，直到success或失败终点。

所有权

capability拥有业务路径模板与Operation语义；BaseRequest拥有Session、中间件、Retry与Polling实现。

失败边界

单次Retry不能重置整个poll_timeout；状态失败、deadline耗尽或传输异常都向上抛。

common/test_context.py::TestContext.add_cleanup / cleanup · 两个完整类方法
def add_cleanup(self, callback: Callable[..., Any], *args: Any, **kwargs: Any) -> None:
    if not callable(callback):
        raise TypeError(f"cleanup callback must be callable, actual: {callback!r}")
    self._cleanup_callbacks.append(_CleanupCallback(callback=callback, args=args, kwargs=dict(kwargs)))

def cleanup(self) -> None:
    errors: list[BaseException] = []
    while self._cleanup_callbacks:
        cleanup_callback = self._cleanup_callbacks.pop()
        try:
            cleanup_callback.callback(*cleanup_callback.args, **cleanup_callback.kwargs)
        except BaseException as exc:  # noqa: BLE001 - cleanup must continue after any callback failure.
            errors.append(exc)

    if errors:
        raise ContextCleanupError(errors)

验收与资源收口

验证

Assertions组合JSONPath存在性和值断言，失败立即抛AssertionError并保留原Response用于诊断。

状态变化

TestContext保存提取变量与cleanup栈；执行后回调被弹出，因此第二次cleanup不重复DELETE。

资源所有权

Test登记“何时清理”，Task/Request执行“如何清理”；Request Session仍由Request生命周期拥有。

失败边界

多个cleanup失败会继续执行剩余回调，最后汇总为ContextCleanupError，避免第一个错误遮蔽资源泄漏。

05 · Reliability

Retry处理单次请求，Polling处理跨请求状态

第一次轮询

503后Retry再次请求得到queued；同一request group包含attempt 1和2。

后续轮询

running与succeeded形成新的request group。

状态机

Polling Recorder观察pending、pending、success。

总预算

poll_timeout约束整个轮询周期，单次Retry不能无限扩张。

场景期望四次poll HTTP响应：503、queued、running、succeeded；Polling循环只有三轮业务状态。

06 · Resources

Response、Context、Capture与Cleanup各有收口者

资源所有者与结束条件

08 · Design choice

设计选择与适用边界

现方案固定一个现有module nodeid，从Test Act纵向追踪Task、capability、Request/BaseRequest、Assertions、Context、Cleanup与机器证据。
替代方案按目录横向浏览所有模块，或把测试环境创建细节与业务调用链混在一起阅读。
选择理由隔离环境创建后，3～4小时可以建立业务输入、状态、资源和证据的完整因果链；前置材料用于验证产物信任与发布边界。
不适用条件要证明全框架覆盖、测试基础设施正确性、性能容量或多协议一致性时，一个普通module场景不具代表性，必须另设专项验证。
