# Flaky 课程逐课验收记录

## 验收规则

每一课必须按下面顺序处理：

```text
编写正文
→ 初学者自上而下阅读审阅
→ 当前基准源码与测试事实核验
→ 知识关系图核验
→ 自测与前后课衔接核验
→ PASS 后才开始下一课
```

`REVISE` 表示存在阻断项，必须修改并重新验收；`PASS` 表示本课没有遗留阻断项。

### 第 1 课审阅说明

- 首次门禁发现校验脚本误把模板拓扑当作固定结构，已改为检查本课实际关系边；这不是正文缺陷。
- 发现并修正一处“缺失”的文字错误。
- 正文没有提前引入状态枚举、阈值、身份字段或数据库。
- 自测覆盖历史归类、稳定失败辨析和“缺失 Observation 不等于 PASS”。

### 第 2 课审阅说明

- 正文只新增 Failure ID 和结果签名，没有提前教授窗口阈值或检测状态。
- Mermaid 图表达两个输入如何汇合生成签名，以及签名相等/不等的判断分支。
- 使用测试助手构造真实模型，并验证 `pass`、`fail:A`、`fail:B` 三种生产函数输出。
- 自测覆盖签名复算、相邻变化、Outcome 与 Signature 的区别，以及 Failure ID 缺失边界。

### 第 3 课审阅说明

- 正文只新增证据窗口、切换计数和证据摘要，没有将统计值提前命名为状态。
- R1～R6 正常路径得到 `6/4/2/3/3/1/fail:A`，复杂路径和自测序列也均由生产函数复算。
- Mermaid 图表达窗口如何分流产生三类统计、再汇合为 `FlakyEvidence`，不是章节目录。
- 自测覆盖分类计数、两类切换、尾部连续数和空历史边界。

### 第 4 课审阅说明

- 正文只新增阈值、自动检测状态和状态迁移，并明确当前默认值不是通用定义。
- R1～R6 的逐前缀结果经生产函数验证为 `OBSERVING/OBSERVING/STABLE/SUSPECTED/SUSPECTED/CONFIRMED`。
- 稳定失败路径经生产函数验证为 `STABLE` 且 `stable_failure_id=A`。
- Mermaid 图表达证据与阈值共同进入当前状态规则，再分为状态保持和迁移。
- 自测覆盖阈值复算、稳定失败、一次变化以及检测状态不拥有执行权。

### 第 5 课审阅说明

- 正文只新增 Case ID 和 Parameter Hash；环境、执行画像、Epoch 留到第 6 课。
- Mermaid 图表达 nodeid 规范化、参数摘要和对象身份的实际汇合关系，以及相同/不同身份的分流。
- `test_quality_identifiers.py` 与 `test_flaky_models.py` 共 23 项通过，覆盖路径规范化、参数摘要稳定性和 Flaky Key 的身份分离。
- 自测覆盖参数从 `case_id` 分离、不同参数不得合并，以及身份相同仍不代表跨环境可比较。

### 第 6 课审阅说明

- 正文新增比较作用域、State Epoch 和 Flaky Key，保持在 3 个核心概念内。
- 五维 Key 任一输入变化即分离，`parallel-pool/gw0` 与 `gw17` 均归一为 `parallel`，均由生产函数验证。
- Mermaid 图表达对象身份、运行条件和周期三路汇合成历史归属键，而非按讲解顺序串列。
- Epoch 明确为保留旧事实并开启新周期，不与自动状态或删除历史混淆。

### 第 7 课审阅说明

- 正文新增 Phase 折叠、决定性 Phase、Observation Candidate 三个概念。
- Mermaid 图表达 Phase 集合、生命周期、FailureRecord 如何共同决定 PASS/FAIL Candidate。
- PASS 路径与 call FAIL + 唯一证据路径的专项测试 2 项通过。
- 明确 Candidate 尚无 Epoch、Flaky Key、Observation ID，且未进入数据库或状态机。

### 第 8 课审阅说明

- 正文新增生命周期完整性、证据唯一性、排除原因三个概念。
- 核心路径只改变 FailureRecord 是否存在，其余六种边界作为同一原则的巩固对照。
- Mermaid 图表达两道可信检查如何串联，并分流为 Candidate 或“零 Candidate + 原因”。
- 专项测试 7 项通过，覆盖不完整、skip 系列、身份冲突、证据缺失/冲突和合法 setup/teardown error。
- 明确零 Candidate 不等于 PASS，排除也不会改写 pytest 原始结果。

### 第 9 课审阅说明

- 正文新增来源合同、内容校验、整包拒绝三个概念，核心案例只改变 manifest 哈希是否匹配。
- 首次自审发现源码摘录变量名和错误码各一处拼写错误，修正后重新通过静态门禁。
- 专项测试 12 项通过，覆盖篡改、Run/manifest 版本与状态、Integrity safe/blocking warning。
- 明确哈希只能证明内容与声明一致，来源级拒绝也不同于单 Invocation 排除。

### 第 10 课审阅说明

- 正文新增 Source Digest、幂等 NOOP、Source Conflict 三个概念。
- Mermaid 图表达 digest 与 Run 账本既有状态共同决定首次/重复/冲突，而不是三个并列术语。
- 专项测试 3 项通过，覆盖重复计数不变、importer 版本不改变来源摘要、同 Run 内容变化不覆盖。
- 不同 Run 复用 digest 仅作为唯一约束参考，没有挤入核心重试推导。

### 第 11 课审阅说明

- 正文新增导入账本、事务边界、回滚三个概念，并即时复用了知识卡 C。
- Mermaid 图表达多步业务写入如何进入同一事务、数量校验后提交、任一步失败后共同回滚。
- 两组专项测试共 3 项通过，覆盖 Run/Epoch/Observation 全回滚及公共写操作只使用一个主连接。
- 明确 Schema 初始化在业务事务之前，migration 原子性留在进阶 A；Observation 提交也不等于状态已投影。

### 第 12 课审阅说明

- 正文新增不可变历史、状态投影、Transition 审计三个概念。
- Mermaid 图表达历史重放后如何更新 State，并仅在状态变化时分支追加 Transition。
- 专项测试共 3 项通过，覆盖 R1～R3 的 1 State/2 Transition、重复评估 NOOP，以及 State/Transition 原子回滚。
- 晚到数据、版本不兼容和 rebuild 均未提前展开，保留给进阶 B。

### 第 13 课审阅说明

- 正文新增 Manual Override、双状态字段、人工动作审计三个概念。
- 源码核验纠正了路线中的理想化假设：人工确认会同时更新 `current_state` 与 `detected_state` 为 `CONFIRMED`；原 `SUSPECTED` 由 Transition/Override 保留。
- Mermaid 图表达请求门禁、两类审计记录、State 更新与 Observation 不变的真实关系。
- 专项测试共 3 项通过，覆盖人工确认主路径、mark-not-flaky 对照和审计/状态原子回滚。

### 第 14 课审阅说明

- 正文新增 Quarantine Governance、Recovery Anchor、Governance Resolution 三个概念。
- Mermaid 图表达责任登记如何进入 Anchor，再由 Anchor 后新证据分流 pending/recovered/regressed。
- 专项测试共 5 项通过，覆盖五个新样本恢复、签名切换退化、取消隔离、开放治理阻止 Epoch reset 和纯恢复算法。
- 明确 `RECOVERED` 可由稳定 FAIL 签名产生，且 `QUARANTINED` 不等于 pytest Skip。

### 第 15 课审阅说明

- 正文新增功能开关、fail-open、事实所有权与可用性三个概念。
- Mermaid 图表达 P0 经开关进入 History/State，异常进入 fail-open，报告按可信性分为真实计数或 unavailable。
- 开关与 Stage 测试 12 项、报告可用性测试 5 项通过；覆盖顺序、依赖、异常隔离、缺失报告和可信零迁移。
- 明确 Flaky 直接依赖 P0 而非 Metrics；fail-open 保护 pytest 结果但不保证诊断完整。
- 15 节主课全部通过单课门禁。

### 进阶 A 审阅说明

- 新增 Migration Ledger、Pre-migration Backup、Atomic Migration Batch 三个概念。

- 专项测试 4 项通过，覆盖首次备份、checksum 漂移、坏批次全回滚、v1→v2 数据保留。

### 进阶 B 审阅说明

- 新增 Deterministic Ordering、Late-observation Reprojection、Explicit Full Rebuild 三个概念。
- Mermaid 图表达单 Run/全量入口怎样共享版本门禁、全历史读取、排序与重放，再分流为 dry-run 或事务写入。
- 晚到测试验证三个 PASS 的 `STABLE` 在 `run-1` FAIL 晚到后重投影为 `SUSPECTED`，迁移审计为 `reprojection / late_observation_reprojection`。
- 源码核验纠正了“rebuild 已支持规则升级”的理想化表述：当前 dry-run/apply 均会拒绝不兼容版本；探针同时验证同版本两种模式的返回范围。
- 明确投影失败不回滚已提交 Observation，并把全历史重放成本自然交给进阶 C。

### 进阶 C 审阅说明

- 新增 Run-level Materialization、Per-key Full-history Replay、Key Scope and Full Rebuild 三个概念，没有扩展新的状态规则。
- Mermaid 图串联当前 Run 模型怎样累积、普通评估/全库 rebuild 怎样选择 Key，以及每 Key 怎样进入无 LIMIT 查询、全前缀重放和计划集合。
- 25 条 Observation 测试验证 `total_observation_count=25`、`sample_size=20`；明确窗口只限制证据摘要，不限制查询与重放。
- 源码断言确认 JSONL 模型整批保留、`fetchall()` 无 `LIMIT`、replay 遍历所有前缀、普通评估与 rebuild 的不同 Key 范围。
- 明确 dry-run 仍执行全库读取与计算，且当前没有归档、快照、分页或增量投影能力；不虚构未经基准测试的容量数字。

### 纵向审阅中的事实纠正

- 统一修正第 13 课前后的理想化模型：`confirm_flaky` 会同时把 `current_state` 与 `detected_state` 更新为 `CONFIRMED`，原 `SUSPECTED` 由 manual Transition 和 Override 保留；两个字段主要在 `QUARANTINED/RECOVERING` 阶段分离。
- 统一修正进阶 B 的 rebuild 边界：当前同版本 dry-run/apply 可用，但两种模式与普通评估共享版本门禁，均不能直接替换不兼容版本的旧 State。
- 将进阶 B 的小写 `run-1`～`run-4` 明确为同一 Case 的独立教学数据库，避免与主线大写 R1～R6 的结果混合。
- 统一修正进阶 C 的窗口解释：`evidence_window_size=20` 限制证据摘要，不限制 JSONL 模型物化量、每 Key 查询量、全历史重放步数或 rebuild Key 数量。
