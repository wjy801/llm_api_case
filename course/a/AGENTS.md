# 课程内容自动化约束

本文件适用于 `course/a` 及其子目录。

## 唯一课程依据

开始任何课程写作、审校或修订前，必须完整读取：

- `框架亮点学习建议.md`
- `课程内容设计规范.md`

课程事实必须以仓库当前源码、测试和真实调用关系为依据。除上述两份规范外，`course` 下其他既有课程只能作为非权威参考，不能作为实现事实来源。

## 写入边界

- 课程正文只写入 `课程正文/`。
- 自动化运行产物只写入 `.course-automation/runtime/`。
- 不修改 `course/a` 之外的框架源码、测试、配置或文档。
- 每次只生成或修订任务指定的一节课，不顺带改写其他课程。

## 事实纪律

- 必须区分：框架存在能力、业务模块启用能力、真实调用链经过能力、外部服务兑现契约。
- 每项重要实现陈述都要能追溯到源码或测试；测试只能证明覆盖或预期，不能替代源码对当前行为的证明。
- 不确定或无法从仓库证明的内容必须明确写成未知、限制或待人工确认，禁止补猜。
- 不把未来规划、设计建议或理想行为写成当前实现。
- 缺失事实不能写成零值、成功或不存在问题。

## 教学纪律

- 严格保持 26 课顺序、统一异步 LLM 案例、身份命名和术语。
- 每课只回答一个核心问题，最多新增 2～3 个核心概念。
- 采用“现象 → 模型 → 机制 → 正常路径 → 复杂路径 → 边界 → 下一课”的顺序。
- 图示先于源码；源码必须在概念模型之后出现，并解释输入、输出、状态变化和异常路径。
- 不设置练习、测验或需要读者自行运行后才能得到的结论。
- 禁止用“显然”“不难发现”“从源码可以看出”“相信读者已经理解”“这里不再赘述”跳过推理。

## 完成标准

一节课只有通过静态结构检查和 `.course-automation/schemas/review.schema.json` 定义的独立审校，才可标记为完成。不得为了通过评分而删除边界、淡化不确定性或虚构证据。
