# Codex CLI 课程持续生成使用说明

这套自动化会按照现有大纲串行生成 26 节课程。它不依赖一个无限延长的对话，而是为每个阶段启动独立的 `codex exec`：

```text
当前源码取证
→ 生成单课正文
→ 独立结构化审稿
→ 未达标则定向返修
→ 再次审稿
→ 保存状态并进入下一课
→ 26 课完成后执行跨课一致性总审
```

默认质量门槛为总分 88/100、事实准确性至少 36/40、能力边界至少 9/10，并且不能存在硬失败、blocker 或 major 问题。每课最多返修两轮。

## 1. 目录说明

```text
course/a/
├─ AGENTS.md                         # 对所有课程代理生效的长期约束
├─ 框架亮点学习建议.md               # 26 课大纲
├─ 课程内容设计规范.md               # 写作硬性规范
├─ 课程正文/                         # 最终课程输出
├─ 自动化使用说明.md
├─ scripts/
│  ├─ Invoke-CoursePipeline.ps1      # 前台执行与核心编排
│  ├─ Start-CoursePipeline.ps1       # 后台启动
│  └─ Get-CourseStatus.ps1           # 查看状态
└─ .course-automation/
   ├─ config.json                    # 质量阈值和路径配置
   ├─ tasks.json                     # 固定的 26 课任务清单
   ├─ prompts/                       # 取证、写作、审稿、返修、总审提示词
   ├─ schemas/                       # 结构化审稿 JSON Schema
   └─ runtime/                       # 运行时状态、证据、日志和审稿报告
```

`runtime/` 默认不会进入 Git，但会保留在本机，供中断恢复和早晨复核。

## 2. 运行前准备

打开 PowerShell：

```powershell
cd D:\Code\Form\llm_api_case\course\a
codex --version
codex login
```

运行期间需要：

- 电脑保持开机且不要自动睡眠。
- 网络连接稳定。
- Codex 登录在整个运行期间有效。
- 仓库源码不要同时进行大规模改动，否则前后课程可能基于不同版本事实。

自动化使用 `--approve-for-me` 配合 `workspace-write` 沙箱，并把 Codex 工作目录固定为 `course/a`。审批请求由 Codex 自动审核，适合无人值守；代理可以读取仓库源码，但只能在课程工作区内写入。脚本不会使用危险的无沙箱参数。

## 3. 第一次使用：先做 DryRun

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -DryRun
```

DryRun 只检查：

- Codex 命令是否存在。
- 两份课程依据是否存在。
- 26 课任务是否完整且没有重复。
- 提示词和 JSON Schema 是否齐全。
- 路径和质量门槛是否可读取。

它不会调用模型，也不会生成课程。

## 4. 先试运行一课

建议先生成第 1 课：

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -FromLesson 1 -ToLesson 1
```

完成后重点查看：

```text
课程正文/第01课-Retry不是失败就再试.md
.course-automation/runtime/evidence/lesson-01-evidence.md
.course-automation/runtime/reviews/lesson-01-review-*.json
.course-automation/runtime/summary.md
```

单课通过后再开始整套课程。需要强制重新生成第 1 课时：

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -FromLesson 1 -ToLesson 1 -Force
```

`-Force` 会重新取证、成稿和审校指定范围，但不会删除旧日志。

## 5. 前台持续生成

生成全部 26 课：

```powershell
.\scripts\Invoke-CoursePipeline.ps1
```

指定一个批次：

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -FromLesson 1 -ToLesson 4
.\scripts\Invoke-CoursePipeline.ps1 -FromLesson 5 -ToLesson 8
```

全部批次完成后，再执行一次不带课次范围的命令。已完成课程会被跳过，随后触发 26 课一致性总审：

```powershell
.\scripts\Invoke-CoursePipeline.ps1
```

默认情况下，某课达到最大返修次数仍未通过时，会标记为 `needs_review` 并继续下一课。这更适合隔夜无人值守。若希望任一课程未达标就立即停止：

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -StopOnFailure
```

如需临时改变返修轮数：

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -MaxRevisionRounds 3
```

模型默认沿用当前 Codex 配置。只有你明确需要固定模型时才传入：

```powershell
.\scripts\Invoke-CoursePipeline.ps1 -Model "你的模型名称"
```

## 6. 后台隔夜运行

```powershell
.\scripts\Start-CoursePipeline.ps1
```

后台运行指定区间：

```powershell
.\scripts\Start-CoursePipeline.ps1 -FromLesson 9 -ToLesson 16
```

查看状态：

```powershell
.\scripts\Get-CourseStatus.ps1
```

后台进程的标准输出和错误输出位于：

```text
.course-automation/runtime/background.out.log
.course-automation/runtime/background.err.log
```

每个 Codex 步骤还会分别保存标准输出与错误流：标准输出使用 `*.jsonl`，错误流使用对应的 `*.jsonl.stderr.log`。普通工具命令返回非零值时，错误流只会被记录，不会再被 PowerShell 误判为编排器自身崩溃；只有整个 Codex 子进程失败时才触发步骤重试。

如果确实需要停止后台任务，先用状态脚本确认 PID，再执行：

```powershell
Stop-Process -Id <确认后的PID>
```

不要凭旧的 `pipeline.pid` 直接终止进程；PID 可能在系统重启后被复用。

## 7. 中断恢复

流水线会在每个阶段保存 `.course-automation/runtime/state.json`。终端关闭、网络短暂失败或机器重启后，重新执行相同命令即可：

```powershell
.\scripts\Invoke-CoursePipeline.ps1
```

- `completed` 且文件仍存在的课程会跳过。
- 已存在的有效源码证据包会复用。
- 已有但尚未纳入状态的课程会保留原稿，先独立审稿，再按问题定向返修；默认不会先整篇重写。
- 已有但未通过的课程会重新审稿并继续返修。
- `failed` 和 `needs_review` 不会被伪装成完成。

如果源码在中断期间发生变化，使用 `-Force` 重新取证，不要复用旧证据。

## 8. 早晨 Review 顺序

先看执行摘要：

```text
.course-automation/runtime/summary.md
```

然后按以下顺序检查：

1. `failed`：通常是网络、认证、权限或模型调用失败。
2. `needs_review`：已生成正文，但质量门槛仍未通过。
3. `.course-automation/runtime/reports/final-audit.json`：跨课术语、事实和衔接问题。
4. 各课最终审稿 JSON 中的 minor 问题。
5. 最后阅读 `课程正文/` 的成稿。

单课的 `completed` 表示通过了当前自动质量门槛，不代表无需人工抽查。重点抽查源码事实、统一案例和第 25～26 课的全局收束。

## 9. 状态含义

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未开始 |
| `researching` | 正在从源码建立证据包 |
| `writing` | 正在生成正文 |
| `reviewing` | 独立审稿中 |
| `revising` | 根据审稿意见定向修订 |
| `completed` | 通过自动质量门槛 |
| `needs_review` | 有正文，但达到最大返修轮数后仍未通过 |
| `failed` | 某个 CLI 步骤或文件校验失败 |

## 10. 成本与时长预期

每课最少需要 3 次模型调用：取证、写作和审稿。26 课最少 78 次调用；如果每课都使用两轮返修，最多约 182 次，再加一次整套课程总审。因此完整运行可能持续数小时，并消耗较多额度。

推荐先跑第 1 课，再按模块分批隔夜执行。批处理不会影响断点恢复，也更便于及时调整统一案例和写作尺度。

## 11. 调整质量门槛

编辑 `.course-automation/config.json`：

```json
{
  "minimum_lesson_characters": 6000,
  "minimum_total_score": 88,
  "minimum_factual_accuracy": 36,
  "minimum_boundary_accuracy": 9,
  "maximum_revision_rounds": 2
}
```

不建议仅为提高通过率而降低事实准确性或能力边界门槛。若课程频繁不通过，应先阅读审稿报告，修正证据范围、统一案例或提示词。
