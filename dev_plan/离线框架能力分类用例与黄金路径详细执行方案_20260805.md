# 离线框架能力分类用例与黄金路径详细执行方案

> 日期：2026-08-05
> 状态：待执行
> 上游思路：`dev/离线框架能力分类用例与黄金路径开发思路_20260805.md`
> 实施范围：新增独立离线示例模块、分类用例、黄金路径及现有报告链路验收

## 1. 目标与完成定义

本方案将离线示例拆成三层：

```text
能力分类用例
→ 黄金路径组合用例
→ Runner / Quality / Jenkins运行级验收
```

完成后应同时满足：

1. 业务测试不连接任何外部接口，只访问本轮fixture提供的loopback地址，不需要真实账号、余额或密钥；依赖安装是否物理断网不属于本方案的业务离线合同。
2. 每个分类用例只验证一个内聚功能集合，失败位置清晰。
3. 黄金路径覆盖Request、Task、Assertions、Decorators、Middleware、Retry、Polling、TestContext、Capture、并发上下文和Runtime Hooks等主要能力。
4. 同一模块可在Quality关闭和开启两种模式下运行。
5. 现有JUnit、Allure、Metrics、Flaky和Pipeline Summary能够消费同一执行事实。
6. 不引入新的测试DSL、DI容器、事件总线、Task注册器、Marker体系或报告体系。

## 2. 实施边界

### 2.1 必须遵守

- 新模块创建Request、Task、Assertions、Decorators四件套，且均为真实类。
- 测试数据使用Python对象表达，不新增YAML、Excel或隐式配置DSL。
- 所有业务请求通过BaseRequest或其子类执行。
- 多请求业务动作只通过`common.runtime_hooks`中性入口表达逻辑调用。
- 业务用例不导入`quality.metrics.*`、`quality.flaky_store.*`或`run_orchestration.*`内部实现。
- 每个线程创建并关闭自己的Request Session。
- 只有真实共享资源才使用`serial`；本模块初版不人为制造共享资源，因此不增加Marker。
- SSE/流式输出已从当前范围删除，本方案不恢复或验证SSE。
- 所有认证信息使用固定离线占位值，禁止复制任何真实凭证。

### 2.2 不在本轮处理

- 不修改现有真实业务用例语义。
- 不重构BaseRequest、BaseTask、Quality、Metrics或Flaky实现。
- 不增加新的Jenkins Job或专用报告。
- 不通过随机失败演示Flaky。
- 不要求单条用例覆盖Polling所有互斥终态。
- 不要求一条用例同时进入并发池和串行池。

## 3. 首要约束与实施策略

TOC判断：首要约束是本地模拟服务的确定性，而不是用例代码。

因果链：

```text
本地服务状态不确定
→ Retry/Polling调用次数不稳定
→ Metrics与报告事实不稳定
→ 分类用例无法定位问题
→ 黄金路径失去学习价值
```

因此执行顺序固定为：

```text
阶段0冻结合同
→ 阶段1实现本地服务
→ 阶段2创建四件套和基础分类
→ 阶段3完成状态、资源和断言分类
→ 阶段4完成并发和黄金路径
→ 阶段5验收运行与报告
→ 阶段6同步文档和发布基线
```

阶段不得跳过。阶段1未证明无外网和可重复前，不进入黄金路径开发。

## 5. 阶段0：冻结离线协议与验收合同

### 5.1 阶段目标

在写具体业务逻辑前，固定接口、响应、状态机、调用次数和稳定nodeid，消除后续反复修改测试预期的问题。

### 5.2 需要确定的合同

#### HTTP接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/media/generations` | 创建异步任务 |
| GET | `/v1/media/tasks/{task_id}` | 查询任务状态 |
| DELETE | `/v1/media/tasks/{task_id}` | 清理任务 |
| GET | `/v1/transient` | 503/429重试 |
| GET | `/v1/context` | JSON/Header/Cookie/Regex提取 |
| GET | `/v1/audit` | 并发控制请求 |
| GET | `/v1/contracts/{mode}` | 正常、错误及Schema异常响应 |
| GET | `/assets/input.png` | 输入资源捕获 |
| GET | `/assets/output.png` | 输出资源捕获 |

#### 状态机

为每个任务保存独立状态序列，禁止使用随机数：

```text
成功链：HTTP 503 → queued → running → succeeded
失败链：queued → failed
未知链：queued → paused
超时链：running → running → ...直到deadline
```

503属于第一次轮询请求的transport响应，Retry在同一Polling尝试中完成挽救；后续才继续业务状态迁移。

#### 稳定标识

- 任务ID使用确定性格式，例如`offline-task-001`。
- operation name使用固定snake_case，不包含任务ID、端口、线程名或时间戳。
- 模型ID固定为`offline-media-model`。
- nodeid由文件名、类名和函数名决定，不使用随机参数ID。

### 5.3 阶段产物

- 在本方案或代码常量中形成唯一接口合同。
- 明确每个分类用例的输入、响应序列和预期调用次数。
- 明确黄金路径的成功链，不混入互斥异常终态。

### 5.4 停止条件

遇到以下情况必须暂停：

- 需要真实外部接口才能产生某项能力事实；
- 需要修改Quality内部模型才能运行示例；
- 需要依靠随机等待保证状态顺序；
- 需要新增Marker区分离线用例。

### 5.5 阶段完成条件

- 接口和状态机没有歧义；
- 每个分类用例有唯一责任；
- 黄金路径步骤和预期请求数量可以被明确列出。

## 6. 阶段1：实现确定性本地服务与fixture

### 6.1 修改文件

```text
新增 module/offline_framework_example/offline_service.py
新增 module/offline_framework_example/conftest.py
```

### 6.2 `offline_service.py`设计

建议使用普通类和标准库，不增加通用Mock Server框架：

```text
OfflineServiceState
├─ lock
├─ tasks
├─ endpoint_call_counts
├─ audit_records
├─ deleted_task_ids
└─ asset_request_events

OfflineService
├─ start()
├─ stop()
├─ base_url
└─ state
```

Handler要求：

- 使用`ThreadingHTTPServer`；
- 绑定`127.0.0.1`和端口0；
- JSON响应统一设置Content-Type和Content-Length；
- 二进制响应使用极小的固定字节内容；
- 覆盖默认控制台日志，避免污染pytest输出；
- 更新状态时必须持锁；
- 未知路径返回结构化404；
- 不启动后台定时器，不使用随机状态变化。

### 6.3 `conftest.py`设计

提供以下fixture：

1. `offline_service`
   - 每个测试启动独立服务；
   - yield服务对象；
   - finally中关闭服务和线程；
   - 验证没有存活服务线程。
2. `offline_capture_dirs`
   - 使用`tmp_path`隔离输入和输出捕获目录；
   - 只在测试层替换捕获目录，不扩张生产API；
   - 保证附件读取期间文件仍存在。
3. `offline_network_guard`
   - 验证示例生成的base URL和资源URL只指向loopback；
   - 不使用全局永久patch；
   - 若检测到非loopback目标立即失败并显示目标主机，不发出请求。

### 6.4 定向验证

- 服务可重复启动和停止至少20次而不冲突；
- 两个服务实例状态相互隔离；
- 同一接口在相同配置下返回相同序列；
- teardown后无服务线程；
- 本地资源接口返回固定Hash。

### 6.5 阶段完成条件

- 本地服务不依赖`.env`中的真实域名和密钥；
- 不存在外部网络请求；
- 所有状态变化可通过计数器解释；
- fixture失败时仍能执行服务关闭。

## 7. 阶段2：创建四件套并完成Request、Middleware、Retry分类

### 7.1 修改文件

```text
新增 module/offline_framework_example/test_request_pipeline.py
新增 module/offline_framework_example/test_retry.py
```

### 7.2 四件套职责

#### `OfflineFrameworkRequest(BaseRequest)`

- 接收本地服务base URL构造离线配置；
- 使用固定离线API Key占位值；
- 定义任务、上下文、审计、清理和合同查询路径；
- 单请求方法使用`runtime_metadata()`；
- workload和control角色准确区分；
- 不覆盖BaseRequest的重试、日志或Middleware实现。

#### `OfflineFrameworkTask(BaseTask)`

- 构建新的payload字典；
- 复用BaseTask现有异步媒体能力；
- 配置离线PollingPolicy和RetryPolicy；
- 提供任务删除和并发审计业务动作；
- 不向BaseTask增加示例专用方法。

#### `OfflineFrameworkAssertions(BaseAssertions)`

- 通用状态码、JSONPath和Schema全部委托BaseAssertions；
- 只增加任务状态、任务ID、审计集合等领域断言；
- 领域断言返回原响应，支持链式调用；
- 错误文本不得包含离线Authorization的完整值。

#### `OfflineFrameworkDecorators(BaseDecorators)`

- 保留真实类和导入路径；
- 提供少量有业务含义的Allure步骤；
- 不复制BaseDecorators算法。

#### `response_schemas.py`

至少定义：

- 创建任务响应Schema；
- Polling成功响应Schema；
- 标准业务错误Schema；
- 审计响应Schema。

Schema只约束稳定字段，不限制无关扩展字段。

### 7.3 Request与Middleware分类用例

`test_request_pipeline.py`建议包含：

1. `test_request_uses_default_middleware_and_runtime_metadata`
2. `test_sensitive_headers_preserve_business_request`
3. `test_middleware_does_not_mutate_original_payload`

验证点：

- 相对路径正确拼接到loopback base URL；
- 服务收到预期Authorization、单次Header和payload；
- 调用方payload执行前后深度相等；
- 使用默认Middleware链，不在示例内重复日志和观察实现；
- operation name稳定。

### 7.4 Retry分类用例

`test_retry.py`建议包含：

1. `test_retry_rescues_transient_get_failure`
2. `test_retry_honors_retry_after`
3. `test_idempotent_post_can_retry`
4. `test_non_idempotent_post_is_not_retried`

验证点：

- 最终响应和服务端计数一致；
- 重试次数不通过日志文本推断，而由服务状态确认；
- 等待时间使用极小固定值；
- POST只有具备Idempotency-Key或明确策略时重试；
- 不用Retry掩盖断言错误和非法请求。

### 7.5 定向命令

```powershell
.\.venv\Scripts\python.exe -m pytest `
  module/offline_framework_example/test_request_pipeline.py `
  module/offline_framework_example/test_retry.py -q
```

执行时应显式使用临时或自定义Allure目录，避免覆盖其他运行产物。

### 7.6 阶段完成条件

- 四件套可从模块包稳定导入；
- Request/Middleware/Retry分类全部离线通过；
- 没有生产框架目录改动；
- 没有真实网络和固定长等待。

### 9.1 修改文件

```text

新增 module/offline_framework_example/test_full_framework_flow.py
```

### 9.2 并发分类用例

`test_concurrency_context.py`建议包含：

1. `test_submit_with_context_preserves_case_ownership`
2. `test_parallel_requests_use_independent_sessions`
3. `test_single_request_headers_do_not_leak_between_workers`

实现规则：

- 只使用`submit_with_context()`提交业务线程；
- 每个线程内部创建Request Client并在finally关闭；
- 不共享`requests.Session`；
- 本地服务使用锁记录审计事实；
- 测试断言结果集合，不依赖线程完成顺序；
- operation name不包含线程ID。

### 9.3 黄金路径用例

稳定nodeid：

```text
module/offline_framework_example/test_full_framework_flow.py::TestFullFrameworkFlow::test_offline_async_media_flow
```

黄金路径固定流程：

```text
构建本地媒体payload
→ 创建异步任务
→ 建立ASYNC_TASK逻辑调用
→ 首次轮询HTTP 503
→ Retry完成挽救
→ queued → running → succeeded
→ 捕获本地输出文件
→ 提取task_id、request_id、cookie和trace_id
→ 并发执行两个control审计请求
→ 校验状态码、JSONPath、Schema和领域关系
→ 执行DELETE清理
→ 验证本地任务与线程全部释放
```

黄金路径不得包含：

- 预期Polling失败、未知或超时；
- `pytest.raises()`包裹核心业务链；
- 手工构造Quality模型；
- 直接读取Flaky数据库；
- 随机参数或随机失败；
- 为了覆盖串行池而增加无意义`serial`。

### 9.4 黄金路径断言

至少验证：

- 最终状态为`succeeded`；
- task_id与创建响应一致；
- request_id、cookie和trace_id均可提取；
- Retry对应端点实际调用次数符合合同；
- Polling状态顺序完整；
- 输出文件来自loopback并满足Hash/大小预期；
- 并发审计结果数量和唯一性正确；
- DELETE后服务端不存在任务；
- 调用方原始payload未被改变。

### 9.5 定向命令

```powershell
.\.venv\Scripts\python.exe -m pytest `
  module/offline_framework_example/test_concurrency_context.py `
  module/offline_framework_example/test_full_framework_flow.py -q
```

### 9.6 阶段完成条件

- 并发用例重复运行无顺序依赖；
- 黄金路径连续运行20次无失败；
- 单次黄金路径目标耗时不超过2秒；
- 没有残留线程、Session、任务或临时文件；
- 分类用例失败时不影响其他用例初始状态。

## 10. 阶段5：Runner、Quality、Metrics、Flaky与Jenkins验收

本阶段不在业务测试中导入报告或质量内部实现，而是通过现有稳定入口执行并检查产物。

检查：

### 10.5 Flaky多轮验收

使用Job独占的绝对数据库路径：

```powershell

```

对同一黄金路径nodeid连续运行多轮，检查：

- 每轮导入一个可信样本；
- nodeid、case_id和param_hash保持稳定；
- 状态机按真实稳定样本变化；
- 不通过人工失败制造Flaky；
- 数据库损坏或锁冲突采用现有明确错误语义。

不得在方案中预设未经验证的具体迁移轮数；应以当前Flaky规则的真实阈值验收。

## 12. 风险与控制

| 风险 | 因果 | 控制方式 |
|---|---|---|
| 本地服务时序不稳定 | 依赖sleep和线程竞争 | 使用计数器、锁和Event，不使用随机等待 |
| 外部网络误访问 | payload或结果URL错误 | 所有URL由服务生成并校验loopback |
| Capture污染仓库 | 默认下载目录固定 | 测试fixture重定向至tmp_path |
| Allure附件找不到文件 | fixture过早清理 | 附件完成前保持tmp_path有效 |
| Session跨线程共享 | 并发测试复用Request | 每线程创建并finally关闭Request |
| Quality测试耦合内部实现 | 业务测试读取内部模型 | 只通过Runner产物做运行级验收 |
| Flaky示例不稳定 | 故意随机失败 | 只积累真实稳定样本 |
| 黄金路径过重 | 混入所有异常分支 | 异常终态留在分类用例 |
| 示例推动核心重构 | 缺少可配置测试边界 | 遇到核心改动需求立即暂停评审 |
| 本地配置依赖真实.env | config导入需要环境 | 执行命令提供合成离线环境值，不读取真实凭证 |
