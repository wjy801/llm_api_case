## 1. 需求理解

阶段 4 要解决的不是“文件数量太多”，而是同一规则或同一底层动作存在多个实现源，导致一次变化需要在多个位置同步修改。

本阶段覆盖五项工作：

1. 配置规则只有一个规范实现源；
2. Assertions 的同步、异步、模块函数和继承入口共享同一实现；
3. Artifact 的 JSON/JSONL 读取、文件 Hash 和基础字段比对共享小型无领域原语；
4. 两个素材独立 CLI 保留原命令、参数、输出和退出码，内部复用 `MaterialLibraryRequest/Task/Assertions`；
5. 结构测试从“精确目录形状”转为保护公共行为、依赖方向和单一所有权。

阶段完成后的目标形态：

```text
配置入口很多，但规则只有一个实现源
Assertions 入口很多，但断言逻辑只有一个实现源
Artifact 消费者很多，但字节读取与 Hash 只有一个实现源
素材 CLI 仍是两个稳定入口，但 HTTP/流程/断言来自四件套
结构测试保护边界，不阻止安全拆分
```

### 1.1 本阶段不做

- 不删除或缩减 Request、Task、Assertions、Decorators 四件套；
- 不把已有真实类替换为简单别名，不改变类身份、MRO、`__name__` 或导入路径；
- 不删除同步、异步或模块级 Assertions 入口；
- 不改变 `Settings`、`settings`、`load_settings()` 的公开行为和初始化时机；
- 不改变 Quality、Semantic、Metrics、Flaky Schema、版本、Hash、SQLite 或指标公式；
- 不建设 Artifact Repository、通用存储平台、DI 容器、CLI 框架或 Service Locator；
- 不重新调整阶段 1～3 的执行事实、Allure 生命周期、Quality Lifecycle 或 Reporting 状态语义；
- 不纳入流式输出/SSE；
- 不纳入密钥治理；
- 不执行真实素材 CLI、真实接口、付费 Smoke、外部下载或真实 Flaky 数据库；
- 不修改用户当前工作区中的 `module/material_library/test_volc_cn_assets.py` 和 `module/test/`。

## 2. 第一性原理与 TOC 约束

### 2.1 去重的本质

重复不是“代码长得像”，而是同一个业务决定必须同步修改多个位置。

判断两个实现是否应合并，必须同时满足：

1. 输入和输出语义相同；
2. 失败边界相同，或可以由调用方翻译；
3. 变化原因相同；
4. 合并后不会迫使低层依赖高层领域模型；
5. 公共入口能够通过兼容委托保留。

因此：

- 文件 SHA256 属于稳定的无领域原语，应该共享；
- Metrics 关系校验、Flaky 可导入规则、Reporting 降级策略变化原因不同，不能合并；
- Assertions 的多个入口已经委托同一同步实现，不需要继续拆；
- 素材 CLI 与四件套操作同一组接口，应共享领域实现；
- 精确文件白名单不是行为合同，应退出核心门禁。

### 2.2 当前因果链

#### 配置

```text
Pydantic 字段/模型校验组织规则
-> util.config_validation 同时提供解析和错误聚合
-> 已有部分委托，但环境选择和最终转换仍重复调用规则
-> 新增配置时需要判断应改 validator、to_settings 还是 util
-> 错误顺序、默认值和选中环境规则容易漂移
```

#### Artifact

```text
Metrics、Flaky、Reporting、Aggregator 都需要读文件并验证 Hash
-> 各模块重复实现 JSON 读取和 SHA256
-> I/O 错误处理与领域错误码混在一起
-> 修复读取边界时需要多处同步
-> 相同字节可能出现不同信任结论
```

#### 素材 CLI

```text
独立 CLI 为快速联调自行实现 urllib、payload、轮询和断言
-> 后续四件套又实现同一素材领域
-> 两个 CLI 合计约 1200 行并继续持有第二套领域事实
-> 接口路径、状态集合或 payload 变化需要修改三套实现
-> CLI 和 pytest 用例可能对同一接口得出不同结论
```

#### 结构测试

```text
为了防止职责重新混乱而精确锁定文件集合和完整 DAG
-> 新增一个职责明确的小文件也必须修改目录白名单
-> 测试失败表达“目录变化”而非“边界破坏”
-> 安全重构成本升高
-> 开发者倾向把新逻辑继续塞入旧文件
```

### 2.3 TOC 决策

阶段 4 的第一约束不是重复代码量，而是“兼容行为缺少可执行快照”。如果直接抽取公共实现，无法判断错误文本、CLI 输出或 Artifact 降级是否回退。

实施顺序必须是：

```text
兼容行为刻画
-> 配置规则单一源
-> Assertions 已有单一源确认
-> Artifact 无领域原语
-> 素材四件套补齐领域能力
-> CLI 改兼容委托
-> 结构测试收口
-> 完整回归
```

素材 CLI 是本阶段变化传播最宽的约束，但应放在公共规则和离线测试稳定后实施，避免把 CLI 的历史行为反向污染公共基类。

## 7. 工作包 4A：兼容快照与失败门禁

任何生产代码调整前先补测试。

### 7.1 配置矩阵

覆盖：

- 中国/海外环境选择；
- 缺失选中环境 URL、Key；
- 未选中环境缺失不报错；
- TRUE/FALSE 大小写；
- 空白、非法布尔、零/负数、非数字；
- URL 尾斜杠；
- 多错误聚合顺序与完整文本；
- `Settings` frozen；
- `settings` 导入时初始化和异常时机；
- util parser 与 `load_settings()` 同一输入的等价结果。

### 7.2 Assertions 等价矩阵

同一个 Response 和输入分别经过：

```text
BaseAssertions().assert_*
await BaseAssertions().async_assert_*
common.assert_*
await common.async_assert_*
领域 Assertions 继承入口
```

断言成功时必须返回同一个 Response；失败时异常类型和核心错误文本一致。通过 monkeypatch/spy 证明 async 与模块入口委托同步方法，不复制算法。

### 7.3 Artifact 等价夹具

用临时目录构造：

- 正常 JSON、空文件、非法 JSON、顶层非对象；
- 正常 JSONL、空行、非法行、非对象行；
- 缺失文件、不可读文件；
- 正确 Hash、缺失 Hash、错误 Hash；
- foreign run_id、Schema/版本/status 不匹配。

在改造前记录 Metrics code、Flaky code、Reporting warning 和 Hash 结果。

### 7.4 素材 CLI 合同

使用 subprocess/argv 注入和假的 Request/Task/Assertions，冻结：

- `--help` 参数清单与退出 0；
- 无效 Key 的消息和退出码；
- 两个 CLI 的成功、断言失败、运行异常退出码；
- quiet/insecure 标志传递；
- flow/keep-resources/observe 参数分支；
- 关键输出标题、步骤顺序、汇总和最终 JSON；
- 不发生真实网络访问。

### 7.5 阶段门禁

新合同在当前代码上必须能刻画行为；只有“CLI 确实未委托四件套”和“Artifact 仍重复”对应的结构/spy 测试允许失败。不得通过删除旧入口让测试变绿。

## 8. 工作包 4B：配置规则单一实现源

### 8.1 规范实现源

以 `util/config_validation.py` 作为无框架依赖的配置规则源。建议增加内部不可变结果类型和一个规范编排函数，例如：

```text
ValidatedSettingsValues
validate_settings_values(environment)
```

它只负责：

- 解析布尔、正数和保留数量；
- 选择 china/overseas；
- 只校验选中环境 URL/Key；
- 规范化 URL 与文本；
- 按当前顺序聚合 `ConfigValidationError`；
- 返回构造 `Settings` 所需的中性值。

该函数不得导入 `config.Settings` 或 Pydantic，避免 util 反向依赖配置门面。

### 8.2 config.py 兼容门面

`config.py` 调整为：

```text
load_dotenv()
-> validate_settings_values(env)
-> Settings.model_validate(...)
-> settings = load_settings()
```

`Settings` 保留 frozen Pydantic 类型。私有 `_EnvironmentSettingsInput` 可以删除或缩成对规范函数的薄适配，但不得继续持有第二套字段规则、环境选择或错误聚合。

### 8.3 禁止变化

- 不改成惰性 `settings`；
- 不接受 `1/yes/on` 等新布尔值；
- 不改变默认海外环境；
- 不把控制 Key、特殊账号 Key 扩大为全局必填；
- 不改变 ConfigValidationError 文本以追求“更友好”；
- 不让业务用例直接调用内部规范结果类型。

### 8.4 验收

- 每条配置规则只有 `util/config_validation.py` 一处条件判断；
- `config.py` 只做 dotenv、公共 Model 和兼容初始化；
- 原配置测试和新增等价矩阵全部通过；
- clean checkout 的合成测试环境继续可导入框架。

## 9. 工作包 4C：Assertions 多入口冻结

当前实现已经满足目标，本工作包默认不修改生产代码。

应做：

1. 增加同步/异步/模块函数委托的 spy 测试；
2. 冻结 `common.__all__` 和函数签名；
3. 冻结 Image/Video 等薄子类的真实身份、基类和导入路径；
4. 保留领域 Assertions 的独立规则；
5. 在规范中明确“多入口兼容面不等于多实现”。

禁止：

- 用函数别名替换类；

## 10. 工作包 4D：Artifact 基础原语共享

### 10.1 新增最小中性模块

建议新增 `util/artifact_io.py`，只依赖标准库，包含最小原语：

```text
read_json_object(path)
read_jsonl_values(path)
file_sha256(path)
compare_file_sha256(path, expected)
exact_field_mismatches(payload, expected_fields)
```

最终函数数量以测试证明的真实重复为准；不为“以后可能用”增加接口。

原语只返回数据或无领域结果，不产生：

- MetricsSourceError；
- FlakyImportError；
- Reporting 中文 warning；
- Schema/版本常量；
- Quality 状态；
- 自动目录创建或写入。

### 10.2 消费者保留翻译层

| 消费者 | 共享内容 | 继续本地拥有 |
| --- | --- | --- |
| Metrics Sources | JSON/JSONL、Hash、基础 exact fields | 关系完整性、错误 code、ArtifactEvidence |
| Metrics Writer | file SHA256 | Manifest 内容与原子写入 |
| Flaky Importer | JSON/JSONL、Hash、基础 exact fields | 可导入规则、source digest、错误 code、状态折叠 |
| Pipeline Quality Source | JSON/JSONL、Hash、基础 exact fields | warning 文本、局部降级、NOT_RUN/NO_DATA |
| Quality/Semantic Aggregator | file SHA256 | shard 归并、完整性和 Manifest |

原模块中已有可导入函数保留为兼容委托，不能让调用方统一改用 `util.artifact_io` 后删除旧路径。

### 10.3 Hash 合同

- 对文件原始 bytes 计算 SHA256；
- 不对 JSON 重新序列化后计算；
- chunk 大小不构成公共合同，但结果必须完全相同；
- 缺失/不可读文件由消费者翻译为当前错误；
- `_full_hash()`、fingerprint、metric bucket 等“规范 JSON 内容 Hash”不是文件 Hash，不迁移。

### 10.4 JSON/JSONL 合同

- 编码继续为 UTF-8；
- 空行处理保持当前消费者语义；
- 行号证据可由原语返回，但错误 code 和提示由消费者决定；
- 顶层对象要求由无领域格式错误表示；
- Pydantic model 校验和 run_id 过滤留在消费者。

### 10.5 验收

- 上述文件 SHA256 只剩一个字节读取实现；
- 三类消费者对同一夹具得出与改造前相同的严格/降级结果；
- 所有 Schema、Manifest、Hash 值和产物 fixture 不变；
- 阶段 3 Reporting import budget不回退：核心 `sources.py` 不因 util 原语加载 Quality；
- 不出现万能 Artifact 类或跨领域 Repository。

## 20. 风险与控制

### 20.1 配置错误文本漂移

风险：移除 Pydantic 私有输入模型后，错误顺序、ValueError 包装或空值行为改变。

控制：先冻结完整错误字符串；规范函数按当前字段顺序聚合；subprocess 验证导入时异常。

### 20.2 过度抽象 Artifact

风险：为了统一三类消费者建立通用 Repository，反而把领域规则耦合到一起。

控制：共享模块只含标准库读取、Hash 和纯比对；错误翻译、Schema 与关系验证留在消费者。

### 20.3 Hash 语义变化

风险：误把文件字节 Hash 改为规范 JSON Hash，导致 Manifest 全部变化。

控制：known digest、现有 fixture 和写入/读取双向等价测试；内容 Hash 函数不迁移。

### 20.4 Reporting 导入预算回退

风险：把 Artifact 原语放入 Quality 根包公开面，导致轻量 Reporting 重新加载重实现。

控制：原语放在 `util` 且只依赖标准库；核心 Source 继续局部加载 Quality Adapter。

### 20.5 CLI 输出或退出码改变

风险：把脚本改成 Task 调用后，AssertionError 提前中断、Management 无法完成汇总，或 `main()` 返回行为变化。

控制：CLI 兼容快照；展示/退出翻译留在脚本；Management 逐 case 捕获并记录。

### 20.6 CLI TLS/quiet 污染全局

风险：`--insecure` 修改全局 requests，`--quiet` 关闭框架其他日志。

控制：只修改当前 MaterialLibraryRequest Session 和当前 CLI 展示对象；测试外部 Session 不受影响。

### 20.7 四件套被别名化

风险：为复用脚本直接把类替换为函数或别名。

控制：类身份/MRO/导出测试；所有新增领域方法进入真实类。

### 20.8 结构测试被过度放松

风险：删除文件集合后，依赖反向和所有权重复失去保护。

控制：每删除一个机械断言，必须用行为、禁止依赖或所有权断言替代；迁移与公共合同测试不删除。

### 20.9 用户素材修改被覆盖

风险：阶段 4 修改同一目录时误格式化或暂存用户的 `test_volc_cn_assets.py`。

控制：所有补丁使用明确文件；每个工作包后检查 `git diff --name-only`；逐文件暂存；不批量格式化目录。

## 21. 回滚策略

- 配置单一源可独立回滚，兼容快照测试保留；
- Assertions 仅测试冻结，原则上无需生产回滚；
- Artifact 消费者逐个迁移、逐个回滚，不能一次删除全部旧 wrapper；
- 素材四件套新增方法可保留，CLI 委托可按脚本分别回滚；
- Pipeline CLI 与 Management CLI 不绑定同一提交；
- 结构测试改写最后实施，回滚生产代码时不得恢复机械文件白名单作为替代；
- 任何回滚不得覆盖阶段 1～3 或用户工作区；
- 不使用破坏性 Git 命令。

## 22. 阶段完成定义

只有同时满足以下条件，阶段 4 才完成：

```text
配置公开 API、默认值、错误文本和初始化时机不变
环境选择与配置规则只有 util.config_validation 一个规范实现源
Assertions sync/async/module/inherited 共享同步实现
所有四件套真实类身份与导出不变
文件 SHA256 只有一个字节读取实现且结果完全等价
JSON/JSONL 基础读取共享，领域错误和降级仍由消费者拥有
Metrics/Flaky code、Schema、Hash、SQLite 行为不变
Reporting warning、NOT_RUN/NO_DATA 与四类直观数据不变
两个素材 CLI 命令、参数、关键输出和退出码不变
素材 CLI 内部复用 MaterialLibrary Request/Task/Assertions
用户 material_library 测试文件未修改
结构测试保护行为、依赖方向和所有权，不再锁死文件集合
统一预收集、pytest 0～5、Allure、Quality Lifecycle 无回退
完整离线回归与 collect-only 门禁通过
未执行真实接口、素材 CLI、外部下载或真实 Flaky 数据库
未混入 SSE、密钥治理、Schema 变更或四件套删减
```

阶段 4 完成代表当前审查路线中的“重复实现治理”完成。它不代表框架以后禁止增加文件，而是新增职责必须有独立变化原因，已有公共入口通过兼容委托保持稳定。
