## 1. 需求理解

阶段 3 要解决的不是“删掉 Quality”，也不是把 Quality 文件继续拆细，而是建立可验证的可选扩展边界：

```text
关闭 Quality
=> 核心 Runner、pytest 收集、普通请求和轻量 Reporting 不加载重实现
=> 不创建 Quality 身份、目录、JUnit 默认文件或机器产物
=> 不改变 pytest/Jenkins 原始执行事实

开启 Quality
=> 当前 Collector、Semantic、Metrics、Flaky、CLI、Schema 和产物完整运行
=> 阶段顺序、fail-open、xdist 分片和报告章节不回退
```

本阶段必须完成：

1. `quality/__init__.py` 改为映射驱动的兼容性懒加载，保留当前全部公开符号和 `__all__`；
2. `quality.pytest_plugin` 保持原插件路径与 pytest 行为，但关闭时不导入 Collector、Semantic、Metrics 或 Flaky 重实现；
3. Runner 只依赖中性的 `QualityRunLifecycle` 协议，不再导入 `quality.models.RunStatus`、Quality 配置或具体阶段模块；
4. Quality 关闭时 Lifecycle 工厂返回轻量 Noop，不创建运行身份、阶段环境和 Quality 产物；
5. Quality 开启时 Lifecycle 继续组合现有初始化、阶段环境、事实归并、Semantic、Metrics 和 Flaky 阶段；
6. Pipeline Reporting 将 Quality 产物读取迁入局部加载的 Source Adapter；
7. `initialize-stages`、`set-stage` 和关闭摘要开关等轻量命令不加载 Quality；
8. 报告明确区分：未启用为 `NOT_RUN`，已启用但产物缺失/损坏为 `NO_DATA`；
9. 建立可重复的 `sys.modules` 导入预算测试，禁止以后重新把重实现拉回核心路径。

本阶段不做：

- 不删除、缩减或改名 Quality、Semantic、Metrics、Flaky、SQLite、治理命令或报告章节；
- 不改变任何 Quality Schema、枚举值、标识规则、Hash 规则、CLI 命令、参数和退出码；
- 不改变阶段 1 的“统一先预收集一次”模型、权威收集、分池、pytest 0～5、execution-result 和报告事实优先级；
- 不改变阶段 2 的 BaseTask、BaseRequest、Polling、Header、Capture 或 Allure 生命周期；
- 不实施阶段 4 的配置校验去重、Assertions 去重、Artifact 校验去重、素材 CLI 复用和结构测试全面改造；
- 不建设 entry point 自动发现、插件市场、DI 容器、Service Locator 或多订阅者事件总线；
- 不恢复或扩展流式输出/SSE；
- 不处理密钥泄露、Secret 扫描或凭证治理；
- 不改变四件套强制创建规范；
- 不执行真实接口、付费 Smoke 或外部下载。

## 2. 第一性原理与 TOC 约束

### 2.1 可选能力的本质

“有开关”不等于“可选”。真正可选必须同时满足：

```text
依赖可选：关闭时不导入重实现
状态可选：关闭时不创建身份、目录或产物
控制流可选：关闭时走 Noop，不散落 if quality_enabled
结论中性：可选能力不能覆盖 pytest/Jenkins 事实
兼容完整：开启后全部能力与公共合同不回退
```

仅在函数入口写 `if not enabled: return`，仍会执行模块导入、类定义和依赖初始化，不满足关闭语义。

### 2.2 当前因果链

```text
quality/__init__.py 为方便导入静态聚合全部符号
-> Python 导入任一 quality 子模块前先执行根包初始化
-> import quality.config 也加载 Collector/Metrics/Flaky/Semantic
-> pytest 兼容插件虽在关闭后短路，但重型模块已经导入
-> Runner 顶层导入 RunStatus、environment、quality_pipeline 和 run_record
-> pipeline_reporting/sources.py 顶层导入多组 Quality 模型
-> Quality 关闭只停止运行逻辑，没有退出核心加载路径
-> 新增任一 Quality 子能力都会继续放大 Runner、pytest 和 Reporting 启动面
```

### 2.3 TOC 决策

阶段 3 的首要约束是“包初始化与顶层依赖使关闭开关失效”。实施顺序固定为：

```text
冻结公共导出与导入预算
-> quality 根包兼容性懒加载
-> pytest 轻量外壳与重实现分离
-> Runner 接入单一 QualityRunLifecycle
-> Reporting Quality Source Adapter 局部加载
-> NOT_RUN / NO_DATA 语义收口
-> enabled/disabled 双路径完整验收
```

如果先改 Runner 或 Reporting，而根包仍静态聚合，任何 `import quality.config` 都会继续加载 41 个模块，局部重构没有实际收益。因此根包懒加载是阶段 3 的前置约束。

## 4. 当前实现与加载证据

### 4.1 实测导入结果

在独立 Python 进程中，当前四条路径均加载 41 个 `quality` 模块：

| 操作 | 当前 `quality*` 模块数 | 不应被动加载但已加载的代表 |
| --- | ---: | --- |
| `import quality.config` | 41 | `quality.metrics.*`、`quality.flaky_store.*`、`quality.semantic_*` |
| `import module.conftest` | 41 | Collector、Metrics、Flaky、Semantic |
| `QUALITY_ENABLE=FALSE; import run_orchestration.runner` | 41 | 全部聚合能力 |
| `QUALITY_ENABLE=FALSE; import pipeline_reporting.__main__` | 41 | Metrics/Flaky/Quality 模型 |

根因不是这些入口主动调用了 41 个模块，而是导入任一 `quality.<submodule>` 都会先执行静态聚合的 `quality/__init__.py`。

### 4.2 代码差距

| 位置 | 当前行为 | 风险 | 阶段 3 目标 |
| --- | --- | --- | --- |
| `quality/__init__.py` | 顶层导入所有公开符号 | 任一子模块导入触发全树 | 静态 `__all__` + symbol/module 映射 + `__getattr__` |
| `quality.pytest_plugin` | 顶层导入 Collector、模型、上下文、Semantic、Adapter | disabled 仍加载重实现 | 轻量兼容外壳按开关注册 runtime 实现 |
| `module/conftest.py` | 始终声明插件字符串 | 插件路径必要，但实现加载过早 | 字符串保持，插件自身负责轻重边界 |
| `runner.py` | 顶层导入 `RunStatus` 和具体 Quality 编排模块 | 核心执行器感知扩展内部 | 只依赖中性 Lifecycle/Status |
| `environment.py` | 顶层导入 config 与 identifiers | import Runner 即进入 Quality | 只由 enabled Lifecycle 局部加载 |
| `pytest_execution.py` | 类型签名直接引用 `QualityRuntimeConfig` | pytest 内核静态依赖 Quality | 兼容 helper 改为结构化/惰性依赖，Runner 走 Lifecycle |
| `quality_pipeline.py` | 正确组合各阶段，但由 Runner 直接调用 | 阶段内部泄漏到 Runner | 保留函数，由 Lifecycle 组合 |
| `pipeline_reporting/sources.py` | 顶层导入 Quality Schema/模型/JUnit | 轻量命令加载全树 | 核心 Source 与 Quality Adapter 分离 |
| `_quality_stage()` | real smoke 开启但 Quality 关闭时仍可能 `NO_DATA` | “未运行”与“运行异常”混淆 | 显式 `quality_enabled` 决定 NOT_RUN/NO_DATA |

## 5. 目标架构

```text
run_master / run_orchestration.runner
  -> pytest 核心执行
  -> QualityRunLifecycle（中性协议）
       ├─ NoopQualityRunLifecycle
       │    └─ disabled：不加载重实现、不创建产物
       └─ EnabledQualityRunLifecycle
            ├─ prepare -> 现有 quality_run_record
            ├─ stage_environment -> 现有 environment
            └─ finalize -> 现有 quality_pipeline
                 ├─ fact merge
                 ├─ final run record
                 ├─ semantic
                 ├─ metrics
                 ├─ flaky history
                 └─ flaky state

module/conftest.py
  -> "quality.pytest_plugin"（稳定插件路径）
       -> disabled / collect-only：轻量外壳直接返回
       -> enabled：局部注册 pytest_plugin_runtime

pipeline_reporting
  -> Core Sources（stage/JUnit/collect/execution）
  -> Quality Source Adapter（仅 Quality 启用且需要报告时导入）
       -> facts / request health / metrics / flaky

quality package
  -> __all__（兼容清单）
  -> __getattr__（按符号加载定义模块并缓存）
```

不新增通用插件注册中心。框架当前只有一个可选 Quality 生命周期，一个显式工厂已经足够。

## 6. 公共兼容边界

### 6.1 必须原样保留

- `quality.__all__` 当前全部名称、顺序和容器语义；
- `from quality import <现有符号>` 的对象身份、`__module__`、类型、签名和返回行为；
- `import quality.metrics`、`quality.flaky_store` 等子包路径；
- `quality.pytest_plugin` 注册路径、pytest Hook 行为、JUnit properties、xdist 分片和 fail-open；
- `QualityRuntimeConfig` 字段、环境变量、默认值和配置错误语义；
- Quality、Semantic、Metrics、Flaky 全部 Schema/版本/枚举/身份/Hash；
- `python -m quality.cli` 的现有命令、参数、stdout/stderr 和退出码；
- `pytest_execution.py` 作为 pytest 收集和执行唯一所有者，以及统一先预收集再分池执行的模型；
- `run_master.run()`、CLI、serial、JUnit、Allure、execution-result 和 pytest 0～5；
- `run_orchestration.environment`、`quality_pipeline.finalize_quality_run()` 等现有内部兼容入口；
- `pipeline_reporting.__all__`、Pipeline Summary/JSON/邮件字段和现有报告章节；
- Quality 产物默认路径、自定义 `QUALITY_OUTPUT_DIR` 和 Flaky 外部 SQLite 路径。

### 6.2 允许的内部变化

- 根包公开符号从静态 import 改为首次访问时加载；
- disabled pytest 不再注册重型运行插件；
- Runner 状态使用中性枚举，enabled Lifecycle 内部映射到 `quality.models.RunStatus`；
- Runner 对 JUnit 参数和阶段环境的调用改由 Lifecycle 提供；
- Reporting 只有在 Quality 确认启用时读取 Quality 产物；
- Pipeline Context/机器摘要可增加 `quality_enabled` 兼容字段，用于区分 NOT_RUN 与 NO_DATA。

### 6.3 明确不兼容的错误语义

以下当前行为不是兼容合同：

- `import quality.config` 被动加载 Metrics、Flaky、Semantic；
- `QUALITY_ENABLE=FALSE` 仍创建 Quality 身份、目录或默认 Quality JUnit；
- Quality 未启用却因旧产物缺失显示 `NO_DATA`；
- 轻量 Reporting 命令导入 Flaky Store；
- 可选扩展异常覆盖 pytest 原始退出码。

## 7. 工作包 3A：公共导出快照与导入预算

### 7.1 公共导出快照

在修改 `quality/__init__.py` 前建立精确合同测试：

- `quality.__all__` 全量名称与顺序；
- 每个名称当前定义模块；
- 类/枚举/函数/常量的对象身份；
- 已登记公共函数签名；
- `from quality import *` 仍能解析全部符号；
- 未知属性仍抛 `AttributeError`；
- `dir(quality)` 包含全部公开名称。

快照保存在测试代码中或由明确 mapping 反向校验，不能运行时扫描包目录形成第二套自动发现系统。

### 7.2 导入预算

使用全新 subprocess，不能在同一 pytest 进程复用已污染的 `sys.modules`：

| 场景 | 允许加载 | 禁止加载 |
| --- | --- | --- |
| `import quality` | `quality` 根包 | 任一重实现子模块 |
| `import quality.config` | `quality`、`quality.config` | collector/semantic/metrics/flaky/store |
| `import run_orchestration.runner` | 0 个 `quality*` | 全部 Quality 模块 |
| disabled Lifecycle 工厂 | 根包与 config | models/collector/semantic/metrics/flaky |
| disabled pytest 插件 | 根包、config、轻量 plugin | runtime plugin 与重实现 |
| `pipeline_reporting initialize-stages` | 0 个 `quality*` | 全部 Quality 模块 |
| `pipeline_reporting set-stage` | 0 个 `quality*` | 全部 Quality 模块 |

导入门禁优先断言禁止前缀，不只锁定总数；这样新增轻量辅助模块不会造成无意义脆弱测试，但任何 Semantic/Metrics/Flaky 回流都会失败。

禁止前缀至少包括：

```text
quality.collector
quality.runtime_context
quality.runtime_adapter
quality.semantic_
quality.metrics
quality.metrics_models
quality.flaky
quality.flaky_importer
quality.flaky_models
quality.flaky_store
```

## 8. 工作包 3B：quality 根包兼容性懒加载

### 8.1 映射结构

`quality/__init__.py` 改为：

```python
__all__ = [原有完整顺序]

_EXPORT_MODULES = {
    "QualityRuntimeConfig": "quality.config",
    "RunStatus": "quality.models",
    "aggregate_run_metrics": "quality.metrics",
    # 覆盖全部现有公开符号
}
```

实现最小 PEP 562 边界：

- `__getattr__(name)`：查映射、`import_module()`、读取同名对象、缓存到 `globals()`；
- `__dir__()`：合并模块已有属性与 `__all__`；
- 未知名称抛标准 `AttributeError`；
- `TYPE_CHECKING` 下可保留静态类型导入，不在运行时执行；
- mapping keys 必须与 `__all__` 精确相等；
- 同一符号重复访问返回同一对象，不包装函数、不复制类、不改变 MRO。

### 8.2 边界

- 不扫描文件系统、`pkgutil`、entry points 或包元数据；
- 不捕获并吞掉真实 ImportError；定义模块损坏时应暴露真实错误；
- 不把子包对象加入现有 `__all__`；
- 不拆改具体 Quality 模型和算法；
- `from quality import *` 会按兼容要求加载全部导出，这是显式重操作，不属于关闭路径。

## 9. 工作包 3C：pytest 轻量兼容插件

### 9.1 两层结构

保留：

```text
module/conftest.py
  pytest_plugins = ("quality.pytest_plugin",)
```

调整为：

```text
quality/pytest_plugin.py
  轻量外壳
  -> collect-only：返回
  -> 解析 QUALITY_ENABLE
  -> disabled：返回
  -> enabled：局部加载并注册 runtime plugin

quality/pytest_plugin_runtime.py
  当前 Collector/Case/JUnit/Semantic/Runtime Hooks 实现
```

### 9.2 轻量外壳合同

- 顶层只使用标准库、pytest 和必要的轻量定义；
- `quality.config` 在 Hook 内局部导入，不能因模块 import 提前加载；
- collect-only 在配置/身份/目录创建前短路；
- disabled 不注册 autouse fixture、不绑定 Runtime Hooks、不创建 output_dir；
- 非法 `QUALITY_ENABLE` 保留当前 warning + disabled/fail-open 语义；
- runtime plugin 注册名称固定，重复 configure 不重复注册；
- xdist controller 与 worker 都通过同一外壳，worker 配置传递语义不变。

### 9.3 enabled runtime 合同

迁移现有实现而不重写算法：

- Case phase/status 映射不变；
- case_id、invocation_id、param_hash 不变；
- JUnit property 名和值不变；
- collection failure integrity issue 不变；
- worker shard 命名和 controller 不重复写入不变；
- Semantic Collector 与 `QualityRuntimeHooks` 绑定/恢复不变；
- Collector 或 Hook 失败不改变 pytest outcome；
- `pytest_unconfigure` 的 ContextVar 和 Collector 清理顺序不变。

不把 pytest Hook 改成框架通用插件平台。

## 10. 工作包 3D：单一 QualityRunLifecycle

### 10.1 中性协议

新增 `run_orchestration/quality_lifecycle.py`，顶层不得导入 `quality.*`，只定义：

```text
RunLifecycleStatus
  FINISHED / PARTIAL / INTERRUPTED

QualityRunLifecycle Protocol
  enabled
  prepare(start_time)
  ensure_junit_args(pytest_args)
  stage_environment(execution_id)
  finalize(start_time, expected_case_count, pool_results, status)

NoopQualityRunLifecycle
create_quality_run_lifecycle()
```

状态值与现有 `quality.models.RunStatus` 值保持一致；enabled 实现内部显式转换，Runner 不导入 Quality 枚举。

### 10.2 工厂决策

```text
局部加载 quality.config
-> 配置非法：输出当前兼容 warning，返回 Noop
-> QUALITY_ENABLE=false：返回 Noop
-> QUALITY_ENABLE=true：局部加载 enabled 实现与现有阶段
```

Noop 必须满足：

- `ensure_junit_args()` 原样返回；
- `stage_environment()` 是无副作用 context manager；
- `prepare()`/`finalize()` 不写文件；
- 不创建 run_id、execution_id；
- 不导入 identifiers、models、collector、semantic、metrics、flaky；
- 任一方法不能改变 pytest 退出码。

### 10.3 enabled 实现

复用而不是替换现有模块：

- `environment.resolve_parent_quality_config()` 继续解析绝对输出目录和 run_id；
- `quality_run_record.write_initial_run_record()` 继续 prepare；
- `environment.quality_stage_environment()` 继续注入/恢复池级环境；
- 无显式 JUnit 时继续生成 `quality/junit/quality*.xml`；
- `quality_pipeline.finalize_quality_run()` 继续执行既定阶段顺序；
- Lifecycle 自身捕获扩展错误并 fail-open，不覆盖 PoolExecutionResult/final exit；
- exit 2/3/4/5 后只传入实际执行池；
- collect-only 在创建 Lifecycle 前返回，保持零副作用。

### 10.4 Runner 与 pytest_execution

`runner.py` 调整后只感知：

- `RunLifecycleStatus`；
- Lifecycle 的四个动作；
- 核心 `PoolExecutionResult`。

阶段 3 只隔离 Quality 依赖，不重新分配 pytest 生命周期所有权：`pytest_execution.py` 继续唯一拥有统一预收集和各池执行；`scheduling.py` 继续只拥有纯分池算法；`runner.py` 继续负责编排，不直接调用 `pytest.main()`。

移除 Runner 顶层对以下模块的依赖：

```text
quality.models
run_orchestration.environment
run_orchestration.quality_pipeline
run_orchestration.quality_run_record
```

`pytest_execution.ensure_quality_junit_args()` 保留为旧测试/内部调用兼容委托，但移除顶层 `QualityRuntimeConfig` 导入；Runner 新路径只调用 Lifecycle。

## 11. 工作包 3E：Reporting Quality Source Adapter

### 11.1 源分层

新增 `pipeline_reporting/quality_sources.py`：

- 局部拥有 Quality run/manifest/metrics/flaky Schema 验证；
- 读取 request health、retry rescue、interface timing、flaky transition；
- 返回 `pipeline_reporting.contracts` 中的中性结果；
- 保留当前 Hash、run_id、status、version 和完整性校验；
- 失败返回 warning/空中性对象，不改变 Jenkins/pytest 事实。

`pipeline_reporting/sources.py` 保留：

- stage status；
- JUnit Summary；
- collect summary；
- execution-result；
- `load_pipeline_sources()` 稳定入口；
- 旧直接 helper 的兼容委托。

仅当 `include_quality=True` 时局部导入 `quality_sources`。Adapter 导入失败也只产生明确 warning，不阻止框架/JUnit 摘要。

### 11.2 JUnit 边界

JUnit 仍复用 `quality.junit.parse_junit_file()` 这一实现源，本阶段不复制解析器。改为仅在确有 JUnit 文件需要解析时局部导入，避免 `initialize-stages`、`set-stage` 和无测试产物的轻量路径加载 Quality。

JUnit 解析器移动或 Artifact 校验去重属于阶段 4，本阶段不提前实施。

### 11.3 报告配置与状态

Pipeline Context 增加兼容字段 `quality_enabled`，来源遵循：

```text
Jenkins/进程 QUALITY_ENABLE
-> .env QUALITY_ENABLE（进程未提供时）
-> 默认 false
```

质量观测阶段判定：

| 接口测试 | Quality | 产物 | 状态 |
| --- | --- | --- | --- |
| 未启用 | 任意 | 任意 | NOT_RUN |
| 被前序阻断 | 任意 | 任意 | BLOCKED |
| 已执行 | 未启用 | 即使存在旧产物 | NOT_RUN |
| 已执行 | 已启用 | 核心产物完整 | PASSED |
| 已执行 | 已启用 | 缺失/损坏/版本不符 | NO_DATA |

Quality 未启用时不得读取陈旧 `reports/quality` 推断本轮结果，也不得因缺失产物发出“质量事实不可用”警告。

### 11.4 轻量 CLI

- `python -m pipeline_reporting initialize-stages` 不加载 Quality；
- `python -m pipeline_reporting set-stage` 不加载 Quality；
- `GENERATE_PIPELINE_SUMMARY=FALSE` 时先短路，不加载 Quality Source Adapter；
- `generate` 且 Quality 未启用时只加载核心/JUnit 源；
- `generate` 且 Quality 已启用时才加载 Adapter；
- 当前命令参数、输出路径和返回码不变。

## 19. 风险与控制

### 19.1 懒加载漏符号或对象身份变化

风险：手工 mapping 漏项，或用 wrapper 替代原函数。
控制：mapping keys == `__all__`，全量逐项 `is` 比较；禁止函数包装和类别名。

### 19.2 循环导入

风险：`quality.__getattr__` 导入定义模块时，定义模块反向访问根包。
控制：内部模块继续使用 `quality.<module>` 直接导入，不改成从根包导入；逐模块冷启动测试。

### 19.3 pytest 动态注册时机

风险：runtime plugin 在 `pytest_configure` 注册过晚，fixture 或 historic Hook 未生效。
控制：使用 pytester 覆盖单进程、收集失败、xdist controller/worker；必要时在 pytest 允许的最早配置 Hook 注册，不改变插件路径。

### 19.4 xdist worker 配置丢失

风险：controller 轻量，worker 未加载重实现或 run_id/execution_id 不一致。
控制：保留 `pytest_configure_node` payload，断言 worker shard 与当前基线等价。

### 19.5 Noop 与 enabled 行为分叉

风险：Runner 到处判断 `enabled`，形成第二套控制流。
控制：Runner 无条件调用 Lifecycle；差异只由工厂返回的对象决定。

### 19.6 Reporting 状态误判

风险：Quality disabled 读取上轮产物显示 PASSED/NO_DATA，或 enabled 缺产物显示 NOT_RUN。
控制：`quality_enabled` 是是否尝试加载 Adapter 的唯一开关；stale artifact 四象限测试锁定。

### 19.7 JUnit 被误当成重型 Quality

风险：为追求 0 import 复制 JUnit 解析器。
控制：本阶段保留单一 `quality.junit` 实现并改为按需局部导入；解析器归属调整留阶段 4 评审。

### 19.8 fail-open 吞掉配置错误

风险：所有 ImportError/ValueError 都静默转 Noop，难以诊断。
控制：保留明确 warning；只保护可选扩展不覆盖 pytest，不能把 enabled 配置异常伪装成正常 Quality 成功。

## 20. 回滚策略

- 根包懒加载可独立回滚；回滚会使导入预算测试重新失败，但不得删除公共合同测试；
- pytest plugin 轻重分离可独立回滚到单文件实现，enabled 行为测试继续保留；
- Lifecycle 可回滚到旧 Runner 接线，但不能保留一半新旧编排形成双所有者；
- Reporting Adapter 可独立回滚，NOT_RUN/NO_DATA 正确性测试不得回滚为旧错误语义；
- 任何回滚不得修改阶段 1 pytest 事实、阶段 2 Allure 生命周期或用户业务文件；
- 不使用 `git reset --hard` 覆盖工作区。
